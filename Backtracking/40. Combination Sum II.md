# 🔢 Combination Sum II — LeetCode #40

## 📌 Problem

Given an array of integers `candidates` and an integer `target`, return all unique combinations where the chosen numbers sum to `target`.

### Important Rules

1. Each number in `candidates` may be used **at most once**.
2. The solution must not contain duplicate combinations.
3. The array may contain duplicate values.

### Example

```text
Input:
candidates = [10,1,2,7,6,1,5]
target = 8

Output:
[
  [1,1,6],
  [1,2,5],
  [1,7],
  [2,6]
]
```

Notice that:

```text
[1,7]
```

and another identical `[1,7]` should not appear.

---

# 🧠 Brute Force Thought Process

We need to find combinations whose sum is exactly:

```text
target
```

At every position, we can decide whether to use a candidate.

But there are two important differences from **Combination Sum #39**:

### Combination Sum #39

A candidate can be reused:

```text
[2,2,3]
```

Therefore:

```text
Pick → same index
```

### Combination Sum II #40

A candidate can be used only once.

Therefore:

```text
Pick → move to next index
```

There is another challenge:

```text
candidates can contain duplicates
```

So we need to avoid generating the same combination multiple times.

This leads to:

```text
Sorting
+
Backtracking
+
Duplicate skipping
+
Pruning
```

---

# 🚀 Approach — Sorting + Backtracking

The overall approach is:

```text
Sort the array
       ↓
Start backtracking
       ↓
Try candidates from current index
       ↓
Skip duplicate choices at the same level
       ↓
Pick candidate
       ↓
Move to i + 1
       ↓
Backtrack
```

The two most important rules are:

```text
1. Duplicate at SAME recursion level → skip
2. After picking → move to i + 1
```

---

# 1️⃣ Sort the Array

First:

```java
Arrays.sort(candidates);
```

For example:

```text
[10,1,2,7,6,1,5]
```

becomes:

```text
[1,1,2,5,6,7,10]
```

Sorting helps us because:

1. Duplicate values become adjacent.
2. We can easily skip duplicate choices.
3. We can stop early when the sum becomes greater than the target.

---

# 2️⃣ Use a For Loop

Unlike Combination Sum #39, here we use:

```java
for(int i = index; i < candidates.length; i++)
```

This allows us to try every candidate from the current position.

For each candidate:

```text
Choose candidate
      ↓
Recursive call
      ↓
Move to i + 1
      ↓
Backtrack
```

---

# 3️⃣ Skip Duplicate Choices

This is the most important line:

```java
if(i > index && candidates[i] == candidates[i - 1]){
    continue;
}
```

Notice:

```java
i > index
```

not:

```java
i > 0
```

Why?

Because we only want to skip duplicates that occur at the **same recursion level**.

---

# 💡 Same Level vs Different Level

This is the most important concept in Combination Sum II.

Suppose:

```text
candidates = [1,1,2]
```

At the first recursion level:

```text
[]
```

we have:

```text
1
1
2
```

The two `1`s are duplicate choices.

So:

```text
Choose first 1
Skip second 1
Choose 2
```

But after choosing the first `1`:

```text
[1]
```

we are at a different recursion level.

Now choosing the second `1` is allowed:

```text
[1,1]
```

Therefore:

```text
Same level → skip duplicate
Different level → duplicate can be used
```

---

# 🔍 Why `i > index`?

Suppose:

```text
index = 0
```

and:

```text
i = 0
```

Then:

```java
i > index
```

is false.

So the first `1` is allowed.

When:

```text
i = 1
```

we have:

```text
i > index
```

and:

```text
candidates[1] == candidates[0]
```

Therefore we skip the second `1` at this level.

---

# 4️⃣ Pick the Candidate

Once the candidate passes the duplicate check:

```java
list.add(candidates[i]);
sum += candidates[i];
```

Then recursively process the remaining candidates:

```java
getCombinations(
    candidates,
    i + 1,
    sum,
    target,
    list
);
```

The important part is:

```java
i + 1
```

because each candidate can be used only once.

---

# 5️⃣ Backtrack

After exploring the branch:

```java
sum -= candidates[i];
list.removeLast();
```

This restores the state before the current candidate was selected.

So we can try the next candidate.

The pattern is:

```text
Choose
  ↓
Explore
  ↓
Undo
  ↓
Try next choice
```

---

# 6️⃣ Pruning

Your solution also has this:

```java
if(sum + candidates[i] > target){
    break;
}
```

This works because the array is sorted.

For example:

```text
candidates = [1,2,5,6,7]
target = 8
```

Suppose:

```text
sum = 7
```

and current candidate is:

```text
5
```

Then:

```text
7 + 5 = 12
```

which is already greater than the target.

Because the array is sorted, every candidate after `5` will be:

```text
>= 5
```

So none of them can work either.

Therefore we can:

```java
break;
```

instead of continuing.

This is an important optimization.

---

# 🔍 Example

Consider:

```text
candidates = [1,1,2,5,6,7,10]
target = 8
```

We start:

```text
index = 0
sum = 0
list = []
```

### Choose first `1`

```text
list = [1]
sum = 1
```

Recursive call starts from:

```text
i + 1
```

So the second `1` can still be considered.

---

### Choose second `1`

```text
list = [1,1]
sum = 2
```

Then choose:

```text
6
```

giving:

```text
[1,1,6]
```

Sum:

```text
1 + 1 + 6 = 8
```

So we add:

```text
[1,1,6]
```

---

### Backtrack

Remove `6`:

```text
[1,1]
```

Try another candidate.

Eventually we generate:

```text
[1,2,5]
[1,7]
[2,6]
```

The duplicate combinations are skipped.

# 🌳 Recursion Structure

For:

```text
[1,1,2]
```

the important idea is:

```text
                         []
                   /      |      \
                  1       2      ...
                /   \
              1      2
             /
            2
```

At the root:

```text
1
1
```

are duplicate choices.

So the second `1` at the same level is skipped.

But after choosing the first `1`:

```text
[1]
```

the second `1` can be chosen:

```text
[1,1]
```

This is why the condition must be:

```java
i > index && candidates[i] == candidates[i - 1]
```

---

### Step 1 — Skip duplicate choices


# 🔧 Your Code

```java
class Solution {

    List<List<Integer>> ansList = new ArrayList<>();

    public List<List<Integer>> combinationSum2(
        int[] candidates,
        int target
    ) {

        // Sort the array so duplicate values are together
        // and we can skip duplicate choices.
        Arrays.sort(candidates);

        getCombinations(
            candidates,
            0,
            0,
            target,
            new ArrayList<>()
        );

        return ansList;
    }

    public void getCombinations(
        int[] candidates,
        int index,
        int sum,
        int target,
        List<Integer> list
    ){

        if(sum == target){
            ansList.add(new ArrayList<>(list));
            return;
        }

        if(index >= candidates.length)
            return;

        if(sum > target)
            return;

        for(int i = index; i < candidates.length; i++){

            // Skip duplicate choices at the same level
            if(i > index && candidates[i] == candidates[i - 1]){
                continue;
            }

            // Because array is sorted
            if(sum + candidates[i] > target){
                break;
            }

            list.add(candidates[i]);
            sum = sum + candidates[i];

            // Include the element
            // Move to i + 1 because each element
            // can be used only once.
            getCombinations(
                candidates,
                i + 1,
                sum,
                target,
                list
            );

            // Backtrack
            sum -= candidates[i];
            list.removeLast();
        }
    }
}
```

# 🔧 Cleaner Version

We can simplify the solution by passing the **remaining target** instead of maintaining `sum`.

```java
class Solution {

    List<List<Integer>> ans = new ArrayList<>();

    public List<List<Integer>> combinationSum2(
        int[] candidates,
        int target
    ){

        Arrays.sort(candidates);

        backtrack(
            candidates,
            0,
            target,
            new ArrayList<>()
        );

        return ans;
    }

    private void backtrack(
        int[] candidates,
        int index,
        int remaining,
        List<Integer> current
    ){

        if(remaining == 0){
            ans.add(new ArrayList<>(current));
            return;
        }

        for(int i = index; i < candidates.length; i++){

            // Skip duplicate choices at the same level
            if(i > index &&
               candidates[i] == candidates[i - 1]){
                continue;
            }

            // Since array is sorted,
            // no later candidate can work either.
            if(candidates[i] > remaining){
                break;
            }

            current.add(candidates[i]);

            // Move to i + 1 because
            // each element can be used only once.
            backtrack(
                candidates,
                i + 1,
                remaining - candidates[i],
                current
            );

            // Backtrack
            current.remove(current.size() - 1);
        }
    }
}
```

This version has the same logic as yours.

# 🔥 Duplicate Handling — The Key Concept

The condition:

```java
if(i > index && candidates[i] == candidates[i - 1])
    continue;
```

means:

```text
Same value
+
Same recursion level
=
Skip duplicate
```

But:

```text
Same value
+
Different recursion level
=
Allowed
```

Example:

```text
[1,1,6]
```

is valid.

We are not saying:

```text
Never use the same value twice.
```

We are saying:

```text
Don't create the same combination through
two equivalent choices at the same level.
```

This distinction is extremely important.

---

# ⚠️ Common Mistakes

## 1. Using `i > 0` Instead of `i > index`

Wrong:

```java
if(i > 0 && candidates[i] == candidates[i - 1])
    continue;
```

This can incorrectly skip a duplicate that is valid at a deeper recursion level.

Correct:

```java
if(i > index && candidates[i] == candidates[i - 1])
    continue;
```

---

## 2. Forgetting to Sort

Without:

```java
Arrays.sort(candidates);
```

duplicates may not be adjacent.

Then:

```java
candidates[i] == candidates[i - 1]
```

cannot reliably detect duplicate choices.

---

## 3. Reusing the Same Element

Wrong:

```java
getCombinations(
    candidates,
    i,
    ...
);
```

Correct:

```java
getCombinations(
    candidates,
    i + 1,
    ...
);
```

because each element can be used only once.

---

## 4. Removing Too Early

Correct order:

```java
list.add(candidates[i]);

getCombinations(...);

list.removeLast();
```

The removal happens **after** exploring the branch.

---

## 5. Forgetting to Restore `sum`

Since your solution maintains:

```java
sum
```

you need:

```java
sum -= candidates[i];
```

after recursion.

Otherwise the next loop iteration will use the wrong sum.

---

# 🎯 Interview Explanation

> "I first sort the candidates so duplicate values become adjacent. Then I use backtracking with a for loop starting from the current index. At each recursion level, if the current value is the same as the previous value, I skip it when `i > index` to avoid duplicate combinations at the same level. Once I choose a candidate, I recurse with `i + 1` because each element can only be used once. Since the array is sorted, if the current sum plus the candidate exceeds the target, I can break because all later candidates are at least as large."

# 🔥 Pattern Recognition

When you see:

```text
Find all combinations
+
Each array element can be used at most once
+
Input may contain duplicates
```

Think:

```text
Sorting
    ↓
Backtracking
    ↓
For loop
    ↓
Skip same-level duplicates
    ↓
Move to i + 1
```

The core template:

```java
for(int i = index; i < nums.length; i++){

    if(i > index && nums[i] == nums[i - 1])
        continue;

    choose(nums[i]);

    backtrack(i + 1);

    undo();
}
```

# 🧩 Generic Template

```java
void backtrack(
    int[] nums,
    int index,
    int remaining,
    List<Integer> current
){

    if(remaining == 0){
        result.add(new ArrayList<>(current));
        return;
    }

    for(int i = index; i < nums.length; i++){

        // Same-level duplicate
        if(i > index && nums[i] == nums[i - 1])
            continue;

        // Pruning
        if(nums[i] > remaining)
            break;

        // Choose
        current.add(nums[i]);

        // Explore
        backtrack(
            nums,
            i + 1,
            remaining - nums[i],
            current
        );

        // Undo
        current.remove(current.size() - 1);
    }
}
```

# ⏱️ Complexity

Let:

```text
n = number of candidates
```

The search space is exponential because we explore combinations of different sizes.

In the worst case, the number of subsets of the input is:

```text
2^n
```

and the recursion explores a large portion of this search space.

So the backtracking search is commonly described as:

```text
O(2^n)
```

ignoring the cost of copying each result.

If we include the cost of copying a combination into the answer, the total cost depends on the number and sizes of valid combinations and can be expressed as:

```text
O(n × 2^n)
```

in the broad worst-case output-sensitive bound.

### Sorting

```text
O(n log n)
```

which is dominated by the exponential search for large `n`.

### Auxiliary Space

Recursion depth:

```text
O(n)
```

Current combination:

```text
O(n)
```

Therefore auxiliary space excluding output:

```text
O(n)
```

### Output Space

Depends on the number of unique combinations and their lengths.
