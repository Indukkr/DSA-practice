# 🌡️ Daily Temperatures — LeetCode #739

## 📌 Problem

You are given an array `temperatures`, where `temperatures[i]` represents the temperature on day `i`.

For every day, find how many days you must wait until a warmer temperature occurs.

If there is no future day with a warmer temperature, store `0`.

### Example

```text
Input:
temperatures = [73,74,75,71,69,72,76,73]

Output:
[1,1,4,2,1,1,0,0]
```

Explanation:

| Day | Temperature | Next warmer day | Days to wait |
|---:|---:|---:|---:|
| 0 | 73 | Day 1: 74 | 1 |
| 1 | 74 | Day 2: 75 | 1 |
| 2 | 75 | Day 6: 76 | 4 |
| 3 | 71 | Day 5: 72 | 2 |
| 4 | 69 | Day 5: 72 | 1 |
| 5 | 72 | Day 6: 76 | 1 |
| 6 | 76 | None | 0 |
| 7 | 73 | None | 0 |

---

# 🧠 Brute Force Thought Process

For every day:

1. Start checking the next day.
2. Continue until a warmer temperature is found.
3. Store the difference between the current day and the warmer day.
4. If no warmer temperature exists, store `0`.

### Example

```text
temperatures = [73,74,75,71]

For day 0:

73 → 74 is warmer
Answer = 1

For day 1:

74 → 75 is warmer
Answer = 1

For day 2:

75 → no warmer temperature
Answer = 0

For day 3:

71 → no warmer temperature
Answer = 0
```

### Brute Force Complexity

There are `n` days, and each day may scan the remaining array.

```text
Time:  O(n²)
Space: O(1) auxiliary space
```

The answer array itself requires `O(n)` space.

We can optimize this using a Monotonic Stack.

---

# 🚀 Optimized Approach — Monotonic Stack

The key observation is:

> For each day, we need the index of the nearest future day whose temperature is strictly greater than the current temperature.

Instead of scanning the future days repeatedly, we maintain a stack of **indices of useful future days**.

We traverse the array from **right to left**.

```java
for(int i = temperatures.length - 1; i >= 0; i--)
```

Why right to left?

Because when processing day `i`, we want to know what happens on days after `i`. By processing from right to left, we have already processed those future days.

---

# 💡 Why Store Indices Instead of Temperatures?

Your stack stores:

```java
Stack<Integer> stack;
```

But these integers represent **indices**, not temperatures.

For example:

```text
temperatures = [73,74,75,71]
```

If the stack contains index `2`, its temperature is:

```java
temperatures[2]  // 75
```

Storing indices gives us two things:

1. The temperature, using `temperatures[stack.peek()]`.
2. The distance between days, using `stack.peek() - i`.

That second calculation is the reason indices are essential.

---

# 🔥 The Three-Step Pattern

For every index `i`:

```text
1. Pop indices whose temperatures are <= current temperature.

2. If the stack is empty:
       ans[i] = 0
   Otherwise:
       ans[i] = stack.peek() - i

3. Push the current index.
```

Let's understand why each step is needed.

---

# 1️⃣ Pop Smaller or Equal Temperatures

Your code:

```java
while(!stack.isEmpty() &&
      temperatures[stack.peek()] <= temperatures[i]) {
    stack.pop();
}
```

Suppose:

```text
temperatures = [73,74,75]
```

We are processing `73`.

A future day with temperature `74` is a better candidate than a future day with temperature `73` or lower.

If a future temperature is less than or equal to the current temperature, it cannot be the answer for the current day.

Therefore, remove it.

Notice the condition:

```java
temperatures[stack.peek()] <= temperatures[i]
```

We use `<=`, not just `<`, because the problem requires a **strictly warmer** temperature.

Equal temperatures do not count.

---

# 2️⃣ Find the Answer

After popping:

```java
if(stack.isEmpty()) {
    ans[i] = 0;
} else {
    ans[i] = stack.peek() - i;
}
```

### Case A — Stack is empty

There is no future day with a warmer temperature.

```text
ans[i] = 0
```

### Case B — Stack is not empty

The top index represents the nearest future day with a warmer temperature.

```java
ans[i] = stack.peek() - i;
```

For example:

```text
Current day = 3
Next warmer day = 5

Days to wait = 5 - 3 = 2
```

---

# 3️⃣ Push the Current Index

```java
stack.push(i);
```

The current day becomes a candidate for earlier days.

Remember:

> We push the index only after calculating the current day's answer. This ensures the current day is not considered its own future day.

Compare:


Pop index `3`.

The stack becomes empty.


Compare:



Compare:

# 🔧 Your Code

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {

        int[] ans = new int[temperatures.length];
        Stack<Integer> stack = new Stack<>();

        // Traverse from right to left
        for(int i = temperatures.length - 1; i >= 0; i--) {

            // Remove temperatures that are smaller
            // than or equal to the current temperature
            while(!stack.isEmpty() &&
                  temperatures[stack.peek()] <= temperatures[i]) {
                stack.pop();
            }

            // Find the nearest warmer day
            if(stack.isEmpty()) {
                ans[i] = 0;
            } else {
                ans[i] = stack.peek() - i;
            }

            // Store the current index
            stack.push(i);
        }

        return ans;
    }
}
```

# 💡 Important Observations

## 1. The stack stores indices

```java
stack.push(i);
```

Not:

```java
stack.push(temperatures[i]);
```

Indices allow us to calculate the number of days to wait.

## 2. Equal temperatures must also be removed

```java
temperatures[stack.peek()] <= temperatures[i]
```

A temperature equal to the current temperature is not warmer.

## 3. The stack is monotonic

After processing and pushing an index, the temperatures represented in the stack are strictly decreasing from top to bottom.

For example:

```text
Stack indices:      [1, 2, 6]
Temperatures:       [74,75,76]
```

The temperatures increase from top to bottom in this particular display, so remember that the **actual stack top is the leftmost element** in this notation. From top to bottom, the temperatures are `74, 75, 76`.

More generally, when listed from the bottom of the stack to its top, candidate temperatures are strictly decreasing.

## 4. Each index is pushed and popped at most once

Even though there is a `while` loop inside a `for` loop, the algorithm is linear overall.

# ⚠️ Common Mistakes

### Mistake 1 — Storing temperatures instead of indices

If you store only temperatures, you cannot directly calculate:

```java
nextIndex - currentIndex
```

Store indices.

### Mistake 2 — Using `<` instead of `<=`

Wrong:

```java
temperatures[stack.peek()] < temperatures[i]
```

This leaves equal temperatures on the stack, even though they are not warmer.

Correct:

```java
temperatures[stack.peek()] <= temperatures[i]
```

### Mistake 3 — Forgetting the distance calculation

The answer is not the next warmer temperature.

It is the number of days to wait:

```java
ans[i] = stack.peek() - i;
```

### Mistake 4 — Forgetting the empty-stack case

If the stack is empty after popping:

```java
ans[i] = 0;
```

No warmer day exists.

# 🎯 Interview Explanation

"I use a monotonic stack of indices and traverse the temperatures array from right to left. For every day, I pop indices whose temperatures are less than or equal to the current temperature because those days cannot be the next strictly warmer day. If the stack becomes empty, I store zero. Otherwise, the top index is the nearest warmer day, so I calculate the distance using `stack.peek() - i`. Finally, I push the current index. Each index is pushed and popped at most once, giving O(n) time complexity."

# ⏱️ Complexity

Let `n = temperatures.length`.

### Time Complexity: O(n)

Every index is:

- Pushed onto the stack at most once.
- Popped from the stack at most once.

Therefore, the total number of stack operations is linear.

### Auxiliary Space Complexity: O(n)

In the worst case, the stack can contain `n` indices.

The answer array also uses `O(n)` space.

```text
Time:  O(n)
Space: O(n) auxiliary, including the output array
```
