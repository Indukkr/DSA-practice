# ⚡ Pow(x, n) — LeetCode #50

## 📌 Problem

Implement:

```java
double myPow(double x, int n)
```

which calculates:

```text
x^n
```

### Example

```text
Input:

x = 2.0
n = 10

Output:

1024.0
```

Because:

```text
2^10 = 1024
```

Another example:

```text
x = 2.0
n = -2

Output:

0.25
```

Because:

```text
2^-2 = 1 / 2^2 = 0.25
```

---

# 🧠 Brute Force Thought Process

The first thought is:

> "I can multiply `x` by itself `n` times."

For example:

```text
2^5

2 × 2 × 2 × 2 × 2
```

Code would look like:

```java
double ans = 1;

for(int i = 0; i < n; i++){
    ans = ans * x;
}
```

### Complexity

```text
Time  → O(n)
Space → O(1)
```

But `n` can be very large.

We need something faster.

---

# 💡 Key Observation

Instead of calculating:

```text
x^n
```

by multiplying `x` `n` times, we can repeatedly divide the exponent by `2`.

For example:

```text
x^10

= (x^5)^2
```

And:

```text
x^5

= (x^2)^2 × x
```

And:

```text
x^2

= (x^1)^2
```

So we can calculate powers recursively using:

```text
n / 2
```

This reduces the exponent by half at every step.

Therefore, the complexity becomes:

```text
O(log n)
```

---

# 🚀 Approach — Binary Exponentiation / Fast Power

The main idea is:

```text
x^n
 ↓
Calculate x^(n/2)
 ↓
Square the result
```

There are two cases.

### Case 1 — Even `n`

If:

```text
n = 10
```

then:

```text
x^10 = x^5 × x^5
```

So:

```text
x^n = halfPower × halfPower
```

---

### Case 2 — Odd `n`

If:

```text
n = 5
```

then:

```text
x^5 = x^2 × x^2 × x
```

So:

```text
x^n = halfPower × halfPower × x
```

Therefore:

```java
if(n % 2 == 0)
    return halfPower * halfPower;
else
    return halfPower * halfPower * x;
```

---

# 🔍 Base Case

When:

```text
n = 0
```

we know:

```text
x^0 = 1
```

Therefore:

```java
if(n == 0)
    return 1;
```

This is also what stops the recursion.

---

# 🔧 Your Approach

Your recursive function:

```java
calculatePower(x, n)
```

first calculates:

```java
calculatePower(x, n / 2)
```

and stores the result:

```java
double halfPower = calculatePower(x, n / 2);
```

Then:

### If `n` is even:

```java
return halfPower * halfPower;
```

### If `n` is odd:

```java
return halfPower * halfPower * x;
```

This is the **Fast Power / Binary Exponentiation** approach.

---

# 🔧 Your Code

```java
class Solution {

    public double calculatePower(double x, int n){

        if(n == 0)
            return 1;

        double halfPower = calculatePower(x, n / 2);

        if(n % 2 == 0)
            return halfPower * halfPower;

        else
            return halfPower * halfPower * x;
    }

    public double myPow(double x, int n) {

        double power = calculatePower(x, Math.abs(n));

        if(n > 0)
            return power;

        else
            return 1 / power;
    }
}
```

# 🧠 Why Does This Work?

The mathematical idea is:

### Even exponent

```text
x^n = x^(n/2) × x^(n/2)
```

Therefore:

```text
x^n = (x^(n/2))²
```

### Odd exponent

For odd `n`:

```text
x^n = x^(n/2) × x^(n/2) × x
```

In integer division:

```text
n / 2
```

automatically gives the smaller half.

For example:

```text
5 / 2 = 2
```

So:

```text
x^5 = x^2 × x^2 × x
```

# 🔄 Negative Exponent

Your `myPow()` handles negative `n` separately.

You calculate:

```java
Math.abs(n)
```

first.

For example:

```text
x = 2
n = -3
```

You calculate:

```text
2^3 = 8
```

Then:

```java
return 1 / power;
```

Therefore:

```text
2^-3 = 1 / 8
     = 0.125
```

The mathematical rule is:

```text
x^(-n) = 1 / x^n
```

# ⚠️ Important Java Edge Case — `Integer.MIN_VALUE`

There is one important issue to know about your current implementation.

You are using:

```java
Math.abs(n)
```

But `n` is an `int`.

The minimum integer value is:

```text
Integer.MIN_VALUE = -2147483648
```

Its positive counterpart:

```text
2147483648
```

cannot be represented by Java's `int`.

Therefore:

```java
Math.abs(Integer.MIN_VALUE)
```

still results in:

```text
-2147483648
```

because of integer overflow.

So your recursive solution has a potential edge-case issue for:

```text
n = -2147483648
```

This is important to know for an interview.

---

# 🔧 Safer Version

One way to avoid the `Math.abs(int)` issue is to use `long` for the exponent:

```java
class Solution {

    public double myPow(double x, int n) {

        long exponent = n;

        if(exponent < 0)
            exponent = -exponent;

        double power = calculatePower(x, exponent);

        if(n < 0)
            return 1 / power;

        return power;
    }

    private double calculatePower(double x, long n) {

        if(n == 0)
            return 1;

        double halfPower = calculatePower(x, n / 2);

        if(n % 2 == 0)
            return halfPower * halfPower;

        return halfPower * halfPower * x;
    }
}
```

The important change is:

```java
long exponent = n;
```

instead of directly doing:

```java
Math.abs(n)
```

# 🧠 Recursion Tree

For:

```text
n = 10
```

the recursion is:

```text
                 10
                /
               5
              /
             2
            /
           1
          /
         0
```

Notice that we're not doing:

```text
10 → 9 → 8 → 7 → ... → 0
```

Instead:

```text
10 → 5 → 2 → 1 → 0
```

The exponent is approximately halved every time.

That's why the complexity is:

```text
O(log n)
```

---

# 🧠 Important Difference From Normal Recursion

This is **not**:

```text
T(n) = 2T(n/2)
```

because we call:

```java
calculatePower(x, n / 2)
```

only **once**.

Then we reuse the result:

```java
halfPower * halfPower
```

Therefore:

```text
T(n) = T(n/2) + O(1)
```

which gives:

```text
O(log n)
```

# ⚠️ Common Mistakes

### 1. Multiplying `x` n times

```java
for(int i = 0; i < n; i++)
    ans *= x;
```

This gives:

```text
O(n)
```

The optimized solution should be:

```text
O(log n)
```

---

### 2. Forgetting the odd case

For:

```text
x^5
```

we cannot simply do:

```text
halfPower × halfPower
```

because:

```text
5 / 2 = 2
```

and:

```text
2 + 2 = 4
```

We need one extra `x`:

```text
x^5 = x^2 × x^2 × x
```

Therefore:

```java
halfPower * halfPower * x
```

---

### 3. Forgetting negative exponents

Remember:

```text
x^(-n) = 1 / x^n
```

---

### 4. Forgetting the `n = 0` case

Always:

```java
if(n == 0)
    return 1;
```

because:

```text
x^0 = 1
```

# 🎯 Interview Explanation

> "The brute-force approach would multiply `x` by itself `n` times, giving O(n). I can optimize this using binary exponentiation. I recursively calculate `x^(n/2)` only once and square that result. If `n` is even, the answer is `halfPower²`; if `n` is odd, I multiply by one extra `x`. This reduces the exponent by half at every recursive call, giving O(log n) time. For negative exponents, I use the property `x^-n = 1/x^n`."
