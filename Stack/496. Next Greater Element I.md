# 📈 Next Greater Element I — LeetCode #496

## 📌 Problem

You are given two arrays:

```text
nums1
nums2
```

`nums1` is a subset of `nums2`.

For every element in `nums1`, find the **next greater element** of that element in `nums2`.

The **next greater element** is the first element to the right that is greater than the current element.

If no greater element exists:

```text
-1
```

### Example

```text
nums1 = [4,1,2]
nums2 = [1,3,4,2]

Output = [-1,3,-1]
```

Explanation:

```text
4 → no greater element → -1

1 → next greater is 3 → 3

2 → no greater element → -1
```

---

# 🧠 Brute Force Thought Process

For every element in `nums1`:

1. Find that element in `nums2`.
2. Start searching to its right.
3. Find the first greater element.
4. If none exists, return `-1`.

For example:

```text
nums2 = [1,3,4,2]

For 1:

1  3  4  2
   ↑
   first greater = 3
```

For `4`:

```text
1  3  4  2
      ↑  ↑
      4  2

No greater element → -1
```

### Brute Force Complexity

For every element in `nums1`, we may scan a large part of `nums2`.

Worst case:

```text
O(nums1.length × nums2.length)
```

This can be improved.

---

# 🚀 Optimized Approach — Monotonic Stack + HashMap

The key observation is:

> We should calculate the next greater element for **every element of nums2 only once**.

Then store the answer in a HashMap.

```text
number → next greater element
```

For example:

```text
nums2 = [1,3,4,2]
```

We calculate:

```text
1 → 3
3 → 4
4 → -1
2 → -1
```

Store:

```text
Map

1 → 3
3 → 4
4 → -1
2 → -1
```

Then for every element in `nums1`, simply do:

```java
map.get(nums1[i])
```

This makes the lookup O(1) average.

---

# 🧠 Why Do We Use a Stack?

The important pattern is:

```text
Next Greater Element
        ↓
Monotonic Stack
```

We process `nums2` from **right to left**.

Why?

Because the next greater element must be somewhere on the **right side**.

When processing an element, the stack contains useful candidates from its right side.

# 🔥 Final Map

After processing the complete array:

```text

4 → -1
2 → -1
```

Then process `nums1`.

For:

```text
nums1 = [4,1,2]
```

We simply do:

```text

map[2] = -1
```

Result:

```text

```

# 🔍 Why Can We Pop Smaller Elements?

This is the most important part of the problem.

Suppose:

```text
Current = 4

Stack:

2
```

Can `2` ever be the next greater element for `4`?

No.

Because:

```text
4 > 2
```

So `2` can never help us.

Therefore:

```java
while(!stack.isEmpty() && nums2[i] > stack.peek())
    stack.pop();
```

removes elements that are useless.

This is the heart of the **Monotonic Stack** pattern.

---

# 💡 Important Observation

After removing all smaller elements:

```text
nums2[i] <= stack.peek()
```

So if the stack is not empty:

```java
stack.peek()
```

is the nearest greater candidate.

Therefore:

```java
if(stack.isEmpty())
    map.put(nums2[i], -1);
else
    map.put(nums2[i], stack.peek());
```

# 🔧 Your Approach

Your solution has two main phases.

### Phase 1 — Build Next Greater Map

```java
for(int i = nums2.length - 2; i >= 0; i--)
```

Process `nums2` from right to left.

For every number:

```text
Remove smaller elements
        ↓
Check stack top
        ↓
Store answer in HashMap
        ↓
Push current element
```

---

### Phase 2 — Build nums1 Answer

```java
for(int i = 0; i < nums1.length; i++){
    ans[i] = map.get(nums1[i]);
}
```

Since the map already contains the answer:

```text
nums1 element → next greater element
```

we can directly retrieve it.

---

# 🔧 Your Code

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {

        int[] ans = new int[nums1.length];

        Stack<Integer> stack = new Stack<>();
        Map<Integer, Integer> map = new HashMap<>();

        map.put(nums2[nums2.length - 1], -1);
        stack.push(nums2[nums2.length - 1]);

        for(int i = nums2.length - 2; i >= 0; i--) {

            while(!stack.isEmpty() && nums2[i] > stack.peek())
                stack.pop();

            if(stack.isEmpty())
                map.put(nums2[i], -1);
            else
                map.put(nums2[i], stack.peek());

            stack.push(nums2[i]);
        }

        for(int i = 0; i < nums1.length; i++) {
            ans[i] = map.get(nums1[i]);
        }

        return ans;
    }
}
```

# 🔧 Cleaner Version

We can simplify the first element initialization and the `if-else`.

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {

        Stack<Integer> stack = new Stack<>();
        Map<Integer, Integer> map = new HashMap<>();

        for(int i = nums2.length - 1; i >= 0; i--) {

            while(!stack.isEmpty() && nums2[i] > stack.peek()) {
                stack.pop();
            }

            map.put(
                nums2[i],
                stack.isEmpty() ? -1 : stack.peek()
            );

            stack.push(nums2[i]);
        }

        int[] ans = new int[nums1.length];

        for(int i = 0; i < nums1.length; i++) {
            ans[i] = map.get(nums1[i]);
        }

        return ans;
    }
}
```

This does exactly the same thing as your solution.

# 🧠 The Three-Step Monotonic Stack Pattern

For **Next Greater Element**, remember:

```text
1. Traverse from RIGHT → LEFT

2. Remove smaller elements

3. Stack top = Next Greater Element
```

In code:

```java
for(int i = n - 1; i >= 0; i--) {

    while(!stack.isEmpty() && nums[i] > stack.peek()) {
        stack.pop();
    }

    answer = stack.isEmpty() ? -1 : stack.peek();

    stack.push(nums[i]);
}
```

This pattern is extremely important.

---

# ⚠️ Common Mistakes

## 1. Traversing from left to right without understanding the pattern

For this version, right-to-left is much easier because the required element is on the right.

---

## 2. Not removing smaller elements

Wrong:

```java
if(nums[i] < stack.peek())
    answer = stack.peek();
```

You need to keep popping while the top is smaller:

```java
while(!stack.isEmpty() && nums[i] > stack.peek())
    stack.pop();
```

---

## 3. Forgetting the empty stack case

If:

```java
stack.isEmpty()
```

then there is no greater element.

Therefore:

```text
answer = -1
```

---

## 4. Pushing before calculating the answer

The current element must not become its own next greater element.

Correct order:

```text
Pop smaller
↓
Find answer
↓
Push current
```

# 🎯 Interview Explanation

If the interviewer asks:

> "Why are you using a stack?"

You can say:

> "For every element, I need the nearest greater element on its right. I process the array from right to left and maintain a monotonic decreasing stack. Before processing the current element, I remove all smaller elements because they cannot be the next greater element for the current value. After removing them, the top of the stack is the nearest greater element. I store this mapping in a HashMap and then use the map to construct the answer for nums1."




