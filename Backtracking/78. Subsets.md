# 🔢 Subsets — LeetCode #78

## 📌 Problem

Given an integer array `nums` containing **unique elements**, return all possible subsets (the power set).

The solution set must **not contain duplicate subsets**.

### Example

```text
Input:
nums = [1,2,3]

Output:
[
  [],
  [1],
  [2],
  [3],
  [1,2],
  [1,3],
  [2,3],
  [1,2,3]
]
```

For `n` elements, there are exactly:

```text
2^n
```

possible subsets.

---

# 🧠 Brute Force Thought Process

For every element, we have exactly **2 choices**:

1. Pick the element
2. Do not pick the element

For example:

```text
nums = [1,2]

                         []
                      /      \
                  Pick 1    Don't Pick 1
                    [1]          []
                   /  \         /  \
               Pick 2 Skip 2 Pick 2 Skip 2
                [1,2]  [1]    [2]    []
```

Therefore:

```text
Each element → 2 choices
n elements   → 2 × 2 × ... × 2
             → 2^n subsets
```

This naturally leads to a **Backtracking / Pick-or-Not-Pick** solution.

---

# 🚀 Approach — Backtracking

We process the array from left to right.

At every index:

```text
Pick nums[index]
OR
Don't Pick nums[index]
```

### Steps

1. Start from `index = 0`.
2. Add the current element to the temporary list.
3. Recursively process the next element.
4. Remove the current element (**backtrack**).
5. Recursively process the next element without picking the current element.
6. When `index == nums.length`, we have formed one complete subset.
7. Add a copy of the current list to the answer.

---

# 🔍 Example

For:

```text
nums = [1,2]
```

### Index = 0

Current element = `1`

We have two choices:

```text
Pick 1
Don't Pick 1
```

### Pick 1

```text
list = [1]
```

Move to index `1`.

For `2`:

```text
Pick 2  → [1,2]
Don't 2 → [1]
```

### Backtrack

After exploring `[1,2]`:

```java
list.remove(list.size() - 1);
```

Now:

```text
list = [1]
```

Then we explore the "don't pick 2" branch.

---

Then we backtrack `1` as well and explore:

```text
Don't Pick 1
```

This gives:

```text
[2]
[]
```

Final result:

```text
[1,2]
[1]
[2]
[]
```

---

# 💡 Important Observation

The most important idea is:

```text
Pick → Explore → Undo
```

In code:

```java
list.add(nums[index]);

getSubsets(nums, index + 1, list);

list.remove(list.size() - 1);
```

The `remove()` is the **backtracking step**.

It restores the list to the state it had before making the current choice.

---

# 🔄 Why Do We Need Backtracking?

Suppose:

```text
nums = [1,2]
```

We first pick `1`:

```text
list = [1]
```

Then pick `2`:

```text
list = [1,2]
```

After this branch is completed, we need to remove `2`:

```text
list = [1]
```

Now we can explore:

```text
Don't Pick 2
```

which gives:

```text
[1]
```

Without removing `2`, the next branch would incorrectly contain `[1,2]`.

So:

```text
Backtracking = Undo the previous choice
```

# 🛑 Base Case

```java
if(index == nums.length){
    ansList.add(new ArrayList<>(list));
    return;
}
```

When:

```text
index == nums.length
```

we have processed every element.

Therefore, the current `list` represents one complete subset.

### Why do we use `new ArrayList<>(list)`?

Because `list` is continuously modified during backtracking.

We need to store a **copy** of its current state.

Correct:

```java
ansList.add(new ArrayList<>(list));
```

Not:

```java
ansList.add(list);
```

Otherwise all entries could refer to the same mutable list.

# 🔧 Your Approach

Your approach follows the classic:

```text
Pick
 ↓
Recursive call
 ↓
Backtrack
 ↓
Don't Pick
 ↓
Recursive call
```

The structure is:

```java
// Pick
list.add(nums[index]);
getSubsets(nums, index + 1, list);

// Backtrack
list.remove(list.size() - 1);

// Don't Pick
getSubsets(nums, index + 1, list);
```

This is exactly the important backtracking pattern to remember.

---

# 🔧 Your Code

```java
class Solution {

    List<List<Integer>> ansList = new ArrayList<>();

    public List<List<Integer>> subsets(int[] nums) {

        getSubsets(nums, 0, new ArrayList<>());
        return ansList;
    }

    public void getSubsets(int[] nums, int index, List<Integer> list) {

        if(index == nums.length){
            ansList.add(new ArrayList<>(list));
            return;
        }

        // Pick the current element
        list.add(nums[index]);
        getSubsets(nums, index + 1, list);

        // Backtrack
        list.remove(list.size() - 1);

        // Do not pick the current element
        getSubsets(nums, index + 1, list);
    }
}
```

# 🔧 Cleaner Version

The same approach can be written with slightly cleaner naming:

```java
class Solution {

    List<List<Integer>> result = new ArrayList<>();

    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0, new ArrayList<>());
        return result;
    }

    private void backtrack(int[] nums, int index, List<Integer> current) {

        if(index == nums.length){
            result.add(new ArrayList<>(current));
            return;
        }

        // Pick
        current.add(nums[index]);
        backtrack(nums, index + 1, current);

        // Undo
        current.remove(current.size() - 1);

        // Don't pick
        backtrack(nums, index + 1, current);
    }
}
```

Both approaches use the **same logic**.

# 🌳 Recursion Tree

For:

```text
nums = [1,2,3]
```

The recursion looks like:

```text
                         []
                    /          \
                Pick 1       Skip 1
                  [1]            []
                /    \         /    \
            Pick 2  Skip 2  Pick 2  Skip 2
             [1,2]   [1]     [2]      []
             /  \    /  \    /  \     /  \
            ... ...  ... ... ... ...  ... ...
```

Every level represents one array element.

```text
Level 0 → decision for 1
Level 1 → decision for 2
Level 2 → decision for 3
```

At each level:

```text
2 choices
```

Therefore:

```text
Number of leaves = 2^n
```

---

# 💡 Why `index + 1`?

Once we make a decision about:

```java
nums[index]
```

we move to:

```java
index + 1
```

because that element has already been processed.

Example:

```text
index = 0 → process nums[0]
index = 1 → process nums[1]
index = 2 → process nums[2]
```

# ⚠️ Common Mistakes

## 1. Forgetting to Backtrack

Wrong:

```java
list.add(nums[index]);
getSubsets(nums, index + 1, list);

// Missing remove()
```

This causes elements from one branch to remain in another branch.

Correct:

```java
list.add(nums[index]);
getSubsets(nums, index + 1, list);
list.remove(list.size() - 1);
```

---

## 2. Adding the Same List Reference

Wrong:

```java
ansList.add(list);
```

Correct:

```java
ansList.add(new ArrayList<>(list));
```

Because `list` is mutable.

---

## 3. Forgetting the "Don't Pick" Branch

We need both:

```java
// Pick
list.add(nums[index]);
getSubsets(nums, index + 1, list);
list.remove(list.size() - 1);

// Don't Pick
getSubsets(nums, index + 1, list);
```

If we only pick elements, we won't generate all subsets.

---

## 4. Wrong Base Case

Correct:

```java
if(index == nums.length)
```

At this point, all elements have been considered.

# 🎯 Interview Explanation

> "For every element, I have two choices: either include it in the current subset or exclude it. I use recursion to explore both choices. Whenever I include an element, I recursively process the next index and then remove the element to backtrack before exploring the exclude branch. When I reach the end of the array, I add a copy of the current list to the result."

# ⏱️ Complexity

There are:

```text
2^n
```

possible subsets.

For every subset, we may copy up to `n` elements.

Therefore:

### Time Complexity

```text
O(n × 2^n)
```

### Space Complexity

The recursion depth is:

```text
O(n)
```

The result itself contains:

```text
O(n × 2^n)
```

elements.

So:

```text
Auxiliary Space: O(n)
Output Space:    O(n × 2^n)
```

# 🔥 Final Takeaway

The most important thing to remember from this problem is not the code.

Remember this pattern:

```text
                 Current Element
                 /             \
              PICK           DON'T PICK
                |                |
             Explore          Explore
                |                |
             BACKTRACK
```

And the fundamental backtracking template:

```java
// Choose
list.add(choice);

// Explore
backtrack(...);

// Undo
list.remove(list.size() - 1);

// Explore next choice
backtrack(...);
```

### One-line memory trick

```text
Backtracking = Choose → Explore → Undo
```

For **Subsets**, every element simply gives us:

```text
Pick OR Don't Pick
```

That is the core pattern you should carry forward to the next backtracking problems.
