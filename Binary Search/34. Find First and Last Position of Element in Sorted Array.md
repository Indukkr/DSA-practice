# 🔍 Find First and Last Position of Element in Sorted Array — LeetCode #34

## 📌 Problem

Given a sorted array `nums` and a target value, find the **starting and ending position** of the target.

If the target is not present, return:

```text
[-1, -1]
```

The algorithm must run in:

```text
O(log n)
```

### Example

```text
nums = [5, 7, 7, 8, 8, 10]
target = 8

Output:

[3, 4]
```

---

# 🧠 Brute Force Thought Process

The first thought is:

> "I can traverse the array and find all positions where `nums[i] == target`."

For example:

```text
nums = [5, 7, 7, 8, 8, 10]
                    ↑  ↑
                   3   4
```

We can scan the complete array:

```java
for(int i = 0; i < nums.length; i++){
    if(nums[i] == target){
        // update first and last
    }
}
```

### Complexity

```text
Time  → O(n)
Space → O(1)
```

But the problem specifically requires:

```text
O(log n)
```

Since the array is **sorted**, we should use **Binary Search**.

---

# 💡 Key Observation

Normal Binary Search finds **any occurrence** of the target.

But here we need:

```text
First occurrence
+
Last occurrence
```

So we perform **Binary Search twice**:

```text
Binary Search #1 → Find First Position
Binary Search #2 → Find Last Position
```

---

# 🚀 Approach — Two Binary Searches

We create two functions:

```java
findStart()
findLast()
```

Both use Binary Search.

The only difference is what we do when:

```java
nums[mid] == target
```

---

# 🔍 Finding the First Position

When:

```java
nums[mid] == target
```

we found a target, but there may be another target on the **left**.

So:

```java
first = mid;
end = mid - 1;
```

We store the current answer and continue searching left.

### Logic

```text
nums[mid] == target
        ↓
Possible first occurrence
        ↓
Store mid
        ↓
Search left
```

Code:

```java
if(nums[mid] == target){
    first = mid;
    end = mid - 1;
}
```

---

# 🔍 Finding the Last Position

When:

```java
nums[mid] == target
```

we found a target, but there may be another target on the **right**.

So:

```java
last = mid;
start = mid + 1;
```

We store the current answer and continue searching right.

### Logic

```text
nums[mid] == target
        ↓
Possible last occurrence
        ↓
Store mid
        ↓
Search right
```

Code:

```java
if(nums[mid] == target){
    last = mid;
    start = mid + 1;
}
```

---

# 🧠 The Most Important Difference

This is the main thing to remember in the interview:

### First Position

When target is found:

```java
first = mid;
end = mid - 1;
```

Meaning:

> "Target mil gaya, but maybe aur target left mein hai."

---

### Last Position

When target is found:

```java
last = mid;
start = mid + 1;
```

Meaning:

> "Target mil gaya, but maybe aur target right mein hai."

---

# 🔧 Your Approach

You maintain two variables:

```java
int first = -1;
int last = -1;
```

Initially:

```text
first = -1
last  = -1
```

This is useful because if the target does not exist, they remain `-1`.

Then you call:

```java
return new int[]{
    findStart(nums, target),
    findLast(nums, target)
};
```

So:

```text
findStart() → first occurrence
findLast()  → last occurrence
```

---

# 🔧 Your Code

```java
class Solution {

    int first = -1;
    int last = -1;

    private int findStart(int[] nums, int target){

        int start = 0;
        int end = nums.length - 1;

        while(start <= end){

            int mid = start + (end - start) / 2;

            if(nums[mid] == target){

                first = mid;
                end = mid - 1;

            }else if(nums[mid] < target){

                start = mid + 1;

            }else{

                end = mid - 1;
            }
        }

        return first;
    }

    private int findLast(int[] nums, int target){

        int start = 0;
        int end = nums.length - 1;

        while(start <= end){

            int mid = start + (end - start) / 2;

            if(nums[mid] == target){

                last = mid;
                start = mid + 1;

            }else if(nums[mid] < target){

                start = mid + 1;

            }else{

                end = mid - 1;
            }
        }

        return last;
    }

    public int[] searchRange(int[] nums, int target) {

        return new int[]{
            findStart(nums, target),
            findLast(nums, target)
        };
    }
}
```

# 🧠 Why Do We Continue Searching After Finding Target?

This is the core concept of the problem.

Normal Binary Search:

```text
target found
    ↓
return mid
```

But here:

### First occurrence

```text
target found
    ↓
save mid
    ↓
search LEFT
```

Because another target might exist on the left.

### Last occurrence

```text
target found
    ↓
save mid
    ↓
search RIGHT
```

Because another target might exist on the right.

---

# 🔄 Binary Search Decision Table

| Condition | First Position | Last Position |
|---|---|---|
| `nums[mid] < target` | `start = mid + 1` | `start = mid + 1` |
| `nums[mid] > target` | `end = mid - 1` | `end = mid - 1` |
| `nums[mid] == target` | Save + go left | Save + go right |

The only difference is the **equal case**.

---

# ⚠️ Common Mistakes

### 1. Returning immediately when target is found

Wrong:

```java
if(nums[mid] == target)
    return mid;
```

This only finds **an occurrence**, not necessarily the first or last.

---

### 2. Forgetting to continue searching

For first:

```java
first = mid;
end = mid - 1;
```

For last:

```java
last = mid;
start = mid + 1;
```

The search must continue after finding the target.

---

### 3. Mixing the directions

Remember:

```text
FIRST → Search LEFT
LAST  → Search RIGHT
```

Easy memory trick:

```text
First → LEFT
Last  → RIGHT
```

---

### 4. Initializing first/last incorrectly

Use:

```java
int first = -1;
int last = -1;
```

If target doesn't exist, the result naturally remains:

```text
[-1, -1]
```

# 🎯 Interview Explanation

> "Since the array is sorted, I can use binary search instead of linear search. I perform binary search twice. In the first search, whenever I find the target, I store the index and continue searching on the left to find the first occurrence. In the second search, whenever I find the target, I store the index and continue searching on the right to find the last occurrence. Both searches take O(log n), so the overall time complexity is O(log n) and the extra space is O(1)."

# ⏱️ Complexity

Let `n` = length of the array.

### Time Complexity

We perform two binary searches:

```text
First occurrence → O(log n)
Last occurrence  → O(log n)
```

Overall:

```text
O(log n) + O(log n)
= O(log n)
```

### Space Complexity

Only a few variables are used:

```text
O(1)
```
