# 🪟 Sliding Window Maximum — LeetCode #239

## 📌 Problem

Given an integer array `nums` and a window size `k`, return the maximum value in every contiguous window of size `k`.

### Example

```text
Input:
nums = [1,3,-1,-3,5,3,6,7]
k = 3

Output:
[3,3,5,5,6,7]
```

Explanation:

```text
Window                 Maximum

[1, 3, -1]                3
[3, -1, -3]               3
[-1, -3, 5]               5
[-3, 5, 3]                5
[5, 3, 6]                 6
[3, 6, 7]                 7
```

---

# 🧠 Brute Force Thought Process

For every window:

1. Identify its `k` elements.
2. Traverse all `k` elements.
3. Find the maximum.
4. Move the window one position to the right.

Example:

```text
nums = [1,3,-1,-3,5]
k = 3

Window 1: [1,3,-1]  → max = 3
Window 2: [3,-1,-3] → max = 3
Window 3: [-1,-3,5] → max = 5
```

There are `n-k+1` windows, and finding the maximum in each window takes `O(k)` time.

### Complexity

```text
Time:  O(n × k)
Space: O(1) auxiliary space
```

The answer array requires `O(n-k+1)` space.

We can optimize this using a **Monotonic Deque**.

---

# 🚀 Optimized Approach — Monotonic Deque

A normal queue does not efficiently maintain the maximum when the window moves.

Instead, we use:

```java
Deque<Integer> dq = new ArrayDeque<>();
```

Your deque stores **indices**, not array values.

The indices are maintained so that their corresponding values are in decreasing order from front to back.

For example:

```text
nums = [1,3,-1]

Deque indices:  [1,2]
Deque values:   [3,-1]

Front → 3
```

The maximum is always at the front.

## Why use a Deque?

A deque allows insertion and removal from both ends in `O(1)` time.

```text
Front                         Back
  ↓                             ↓
Remove expired index     Remove smaller values
  ↓                             ↓
pollFirst()                  pollLast()
```

This is exactly what the sliding window problem requires.

---

# 🔥 Three Important Steps

For every index `i`, your algorithm performs three operations.

## 1️⃣ Remove Indices Outside the Window

Your code:

```java
if(!dq.isEmpty() && dq.peekFirst() <= i-k)
    dq.pollFirst();
```

The current window is:

```text
[i-k+1, i]
```

Therefore, any index smaller than `i-k+1` is outside the window.

Equivalent condition:

```java
dq.peekFirst() < i-k+1
```

which simplifies to:

```java
dq.peekFirst() <= i-k
```

### Example

```text
nums = [1,3,-1,-3,5]
k = 3
```

When `i = 3`, the current window is:

```text
[3,-1,-3]
```

The valid indices are:

```text
[1,2,3]
```

Index `0` is outside the window, so it must be removed if it is at the front of the deque.

---

## 2️⃣ Remove Smaller Elements From the Back

Your code:

```java
while(!dq.isEmpty() && nums[i] >= nums[dq.peekLast()]){
    dq.pollLast();
}
```

This is the most important step.

Suppose the current element is `5`, and the deque contains candidates with values:

```text
Deque values:

6
3
```

The value `3` cannot be the maximum of any future window that contains the current `5` but excludes the earlier `6`.

Why?

Because:

- `5` is larger than `3`.
- `5` occurs later than `3`.
- Therefore, `5` will remain in the window at least as long as `3`.

So `3` is no longer useful and can be removed.

The rule is:

> If the current value is greater than or equal to a value at the back of the deque, remove that back element.

This keeps the deque monotonic.

### Why use `>=` instead of `>`?

Equal values have the same maximum value, but the newer index stays in the window longer.

Therefore, removing the older equal value is safe.

---

## 3️⃣ Add the Current Index

Your code:

```java
dq.offerLast(i);
```

After removing expired indices and smaller candidates, insert the current index at the back.

Now the deque contains useful candidates for the current and future windows.

---

# 💡 When Is a Window Ready?

Your code:

```java
if(i >= k-1){
    ans[ptr++] = nums[dq.peekFirst()];
}
```

A window of size `k` becomes complete when:

```text
i = k - 1
```

For example, if `k = 3`:

```text
i = 0 → window incomplete
i = 1 → window incomplete
i = 2 → first complete window
i = 3 → second complete window
```

Therefore:

```java
i >= k-1
```

is the correct condition.

Once a valid window exists:

```java
nums[dq.peekFirst()]
```

gives its maximum.

# 🌳 Deque Evolution

Let's understand the most important transitions.

## Window 1: `[1,3,-1]`

Process `1`:

```text
Deque: [1]
```

Process `3`:

```text
3 >= 1

Remove 1

Deque: [3]
```

Process `-1`:

```text
-1 < 3

Deque: [3,-1]
```

Maximum:

```text
3
```

## Window 2: `[3,-1,-3]`

Process `-3`:

```text
Deque: [3,-1,-3]
```

Index `1`, which contains `3`, is still valid.

Maximum:

```text
3
```

## Window 3: `[-1,-3,5]`

Process `5`:

```text
5 >= -3 → remove -3
5 >= -1 → remove -1
```

The old `3` is also removed because:

```text
5 >= 3
```

Deque:

```text
[5]
```

Maximum:

```text
5
```

This demonstrates why removing smaller elements from the back is so effective.

# 🔧 Your Approach

Your code follows this sequence:

```text
For each index i
       |
       v
Remove expired index from front
       |
       v
Remove smaller/equal values from back
       |
       v
Add current index
       |
       v
Is window size at least k?
       |
       +---- No ---> Continue
       |
       +---- Yes
               |
               v
      Maximum = nums[dq.peekFirst()]
               |
               v
         Store in answer
```

This is the standard optimal solution.

---

# 🔧 Your Code

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {

        int n = nums.length;
        int[] ans = new int[n-k+1];
        int ptr = 0;

        Deque<Integer> dq = new ArrayDeque<>();

        for(int i = 0; i < n; i++){

            // Remove indices outside the current window
            if(!dq.isEmpty() && dq.peekFirst() <= i-k)
                dq.pollFirst();

            // Remove smaller or equal values
            while(!dq.isEmpty() && nums[i] >= nums[dq.peekLast()]){
                dq.pollLast();
            }

            // Add current index
            dq.offerLast(i);

            // Store maximum when window is complete
            if(i >= k-1){
                ans[ptr++] = nums[dq.peekFirst()];
            }
        }

        return ans;
    }
}
```

# 💡 Important Observations

## 1. The deque stores indices, not values

```java
dq.offerLast(i);
```

Indices are required to determine when elements leave the window.

They also let us access the corresponding values:

```java
nums[dq.peekFirst()]
```

## 2. The front always gives the maximum

The deque maintains decreasing values from front to back.

Therefore:

```java
nums[dq.peekFirst()]
```

is the maximum of the current window.

## 3. Every element is processed efficiently

An index enters the deque once and leaves at most once.

It may leave from:

- The front, because it expires.
- The back, because a newer and larger value makes it unnecessary.

## 4. The answer array size is `n-k+1`

For an array of length `n` and window size `k`, the number of complete windows is:

```text
n-k+1
```

Therefore:

```java
int[] ans = new int[n-k+1];
```

is correct.

---

# ⚠️ Common Mistakes

### 1. Storing values instead of indices

Without indices, it is difficult to determine whether an element has expired from the window.

### 2. Removing smaller elements from the front

Smaller elements should be removed from the **back**.

Expired indices should be removed from the **front**.

### 3. Using the wrong expiration condition

Correct:

```java
dq.peekFirst() <= i-k
```

This removes indices outside the current window.

### 4. Forgetting to remove equal values

Using `>=` ensures older equal values are discarded in favor of newer ones.

### 5. Reading the maximum from the back

The maximum is at:

```java
dq.peekFirst()
```

not `dq.peekLast()`.

# 🎯 Interview Explanation

"I use a monotonic deque that stores indices in decreasing order of their corresponding values. For each index, I first remove indices that are outside the current window. Then I remove elements from the back while their values are smaller than or equal to the current value, because they can no longer be useful maximum candidates. I insert the current index at the back. Once the first complete window is formed, the value at the front is the maximum. Since each index is inserted and removed at most once, the algorithm runs in O(n) time."

# ⏱️ Complexity

Let `n = nums.length`.

### Time Complexity: O(n)

Each index is inserted into the deque once and removed at most once.

Although there is a `while` loop inside the `for` loop, the total number of deque operations across the entire algorithm is linear.

```text
Time = O(n)
```

### Auxiliary Space Complexity: O(k)

The deque contains at most `k` indices from the current window.

The answer array contains `n-k+1` elements.

```text
Deque:  O(k)
Output: O(n-k+1)
```

Total space including the output array:

```text
O(n)
```
