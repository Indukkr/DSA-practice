# 🔤 Decode String — LeetCode #394

## 📌 Problem

Given an encoded string, decode it using the following pattern:

```text
k[encoded_string]
```

The encoded string inside the brackets must be repeated `k` times.

The input is guaranteed to be valid.

### Example 1

```text
Input:
s = "3[a]2[bc]"

Output:
"aaabcbc"
```

Explanation:

```text
3[a]  → aaa
2[bc] → bcbc

Final = aaabcbc
```

### Example 2

```text
Input:
s = "3[a2[c]]"

Output:
"accaccacc"
```

Explanation:

```text
2[c]   → cc
a2[c]  → acc
3[acc] → accaccacc
```

---

# 🧠 Brute Force Thought Process

The encoded string contains:

- Digits representing repetition counts.
- Opening brackets `'['`.
- Closing brackets `']'`.
- Ordinary characters.

The challenge is that brackets can be **nested**.

For example:

```text
3[a2[c]]
```

We must decode the innermost expression first:

```text
2[c] → cc
```

Then:

```text
a + cc → acc
```

Finally:

```text
3[acc] → accaccacc
```

A simple left-to-right replacement approach becomes complicated when expressions are nested.

The stack is a natural solution because it helps us process the most recently opened bracket first.

---

# 🚀 Optimized Approach — Stack + StringBuilder

We use:

```java
Stack<Character> stack = new Stack<>();
```

The algorithm processes the input character by character.

## Step 1 — Push characters

If the current character is not `']'`, push it onto the stack.

```java
if (s.charAt(i) != ']') {
    stack.push(s.charAt(i));
}
```

This includes:

```text
Letters
Digits
Opening brackets '['
```

For example:

```text
s = "3[a]"
```

Before reaching `']'`, the stack contains:

```text
Top → [
      a
      3
```

## Step 2 — Decode when `']'` is encountered

When we encounter a closing bracket, we know that a substring is ready to be decoded.

First, extract the characters until `'['` is found.

```java
StringBuilder sb = new StringBuilder();

while (stack.peek() != '[') {
    sb.insert(0, stack.pop());
}
```

Why use `insert(0, ...)`?

Because the stack pops characters in reverse order.

For example, if the encoded substring is `abc`, the stack pops:

```text
c → b → a
```

Inserting every character at the beginning reconstructs:

```text
abc
```

After that, remove the opening bracket:

```java
stack.pop();
```

## Step 3 — Extract the repetition count

The digits immediately before `'['` represent the number of repetitions.

```java
StringBuilder num = new StringBuilder();

while (!stack.isEmpty() &&
       Character.isDigit(stack.peek())) {
    num.insert(0, stack.pop());
}
```

Then:

```java
int number = Integer.parseInt(num.toString());
```

For example:

```text
12[ab]
```

The extracted number is `12`, not `2` or `21`.

This works for multi-digit repetition counts.

## Step 4 — Repeat the decoded substring

```java
StringBuilder repeated = new StringBuilder();

for (int j = 0; j < number; j++) {
    repeated.append(sb);
}
```

For example:

```text
number = 3
sb = "ab"
```

The result becomes:

```text
ababab
```

## Step 5 — Push the decoded characters back

```java
for (int j = 0; j < repeated.length(); j++) {
    stack.push(repeated.charAt(j));
}
```

Why push them back?

Because the decoded substring may be part of a larger expression.

For example:

```text
3[a2[c]]
```

After decoding `2[c]`, we push `cc` back onto the stack. The outer expression can then decode `acc` three times.

Input:

s = "3[a2[c]]"

### Step 1 — Process `3[a2[c`

These characters are pushed onto the stack.

Stack contents, bottom to top:

### Step 2 — Encounter the first `']'`

Remove `'['`.

Then extract the repetition count:

```text

```

Repeat:

```text

```

Push `cc` back onto the stack.

```text

```

Extract characters until `'['`:

```text
Extracted substring = "acc"
```

Remove `'['`.

Extract the repetition count:

```text
number = 3
```

Repeat:

```text
"acc" × 3 = "accaccacc"
```

Push the result back onto the stack.

There are no more encoded brackets.

Pop the remaining characters and construct the string:

```text

```

```text

```

# 🔧 Your Code

```java
class Solution {
    public String decodeString(String s) {

        Stack<Character> stack = new Stack<>();

        for (int i = 0; i < s.length(); i++) {

            if (s.charAt(i) != ']') {
                stack.push(s.charAt(i));
            } else {

                // Extract the string inside brackets
                StringBuilder sb = new StringBuilder();

                while (stack.peek() != '[') {
                    sb.insert(0, stack.pop());
                }

                stack.pop(); // Remove '['

                // Extract the number before '['
                StringBuilder num = new StringBuilder();

                while (!stack.isEmpty() &&
                       Character.isDigit(stack.peek())) {
                    num.insert(0, stack.pop());
                }

                int number = Integer.parseInt(num.toString());

                // Repeat the decoded string
                StringBuilder repeated = new StringBuilder();

                for (int j = 0; j < number; j++) {
                    repeated.append(sb);
                }

                // Push decoded characters back onto stack
                for (int j = 0; j < repeated.length(); j++) {
                    stack.push(repeated.charAt(j));
                }
            }
        }

        // Construct final answer
        StringBuilder ansStr = new StringBuilder();

        while (!stack.isEmpty()) {
            ansStr.insert(0, stack.pop());
        }

        return ansStr.toString();
    }
}
```

# 💡 Important Observations

## 1. Why does nested decoding work?

The innermost closing bracket is encountered first.

For:

```text
3[a2[c]]
```

The algorithm decodes:

```text
2[c]
```

before decoding:

```text
3[acc]
```

This follows the Last In, First Out property of a stack.

## 2. Why use `Character.isDigit()`?

The repetition count may contain multiple digits.

For example:

```text
12[ab]
```

The algorithm collects both `'1'` and `'2'`, reconstructs `"12"`, and converts it to an integer.

## 3. Why push decoded characters back?

The decoded text might belong to an outer expression.

```text
3[a2[c]]
```

Decoding `2[c]` gives `cc`. Those characters must remain available to form `acc`.

## 4. Why does the final loop use `insert(0, ...)`?

Characters are popped in reverse order.

Inserting each character at index `0` reconstructs the original string.

However, repeatedly inserting at the beginning can be expensive.

# 🔧 Cleaner Alternative — Two Stacks

A common alternative uses one stack for repetition counts and another for the strings built so far.

```java
class Solution {
    public String decodeString(String s) {

        Stack<Integer> countStack = new Stack<>();
        Stack<StringBuilder> stringStack = new Stack<>();

        StringBuilder current = new StringBuilder();
        int number = 0;

        for (int i = 0; i < s.length(); i++) {

            char ch = s.charAt(i);

            if (Character.isDigit(ch)) {
                number = number * 10 + (ch - '0');
            }
            else if (ch == '[') {
                countStack.push(number);
                stringStack.push(current);

                current = new StringBuilder();
                number = 0;
            }
            else if (ch == ']') {
                int repeat = countStack.pop();
                StringBuilder previous = stringStack.pop();

                for (int j = 0; j < repeat; j++) {
                    previous.append(current);
                }

                current = previous;
            }
            else {
                current.append(ch);
            }
        }

        return current.toString();
    }
}
```

### How the two-stack approach works

- `countStack` stores repetition counts.
- `stringStack` stores the strings built before each opening bracket.
- `current` stores the substring currently being decoded.
- When `']'` is encountered, repeat `current` and append it to the previous string.

This avoids pushing every decoded character individually onto a character stack.

Both approaches are valid. Your original approach is useful for understanding how a single stack handles nested expressions.

# ⚠️ Common Mistakes

### 1. Forgetting multi-digit counts

Incorrect logic may interpret `12[ab]` as `2[ab]`.

Use `Character.isDigit()` in a loop to extract all digits.

### 2. Forgetting to remove `'['`

After extracting the inner string:

```java
stack.pop();
```

removes the opening bracket before extracting the repetition count.

### 3. Decoding the outer expression too early

Always decode when `']'` is encountered. This naturally handles nested expressions from the inside out.

### 4. Reversing the extracted substring

The stack returns characters in reverse order. Reconstruct the substring in the correct order before repeating it.

### 5. Ignoring string-building costs

`StringBuilder.insert(0, character)` shifts existing characters. Repeating this operation can make the algorithm slower than necessary for large intermediate strings.

# 🎯 Interview Explanation

"I use a stack to process the encoded string from left to right. I push characters until I encounter a closing bracket. At that point, I pop characters until the opening bracket to recover the encoded substring, then extract the repetition count immediately before it. I repeat the substring the required number of times and push the decoded characters back onto the stack. This naturally handles nested expressions because inner brackets are decoded before outer brackets."

# ⏱️ Complexity

Let:

- `n` = encoded input length.
- `L` = decoded output length.

The output can be much larger than the input because of repetition.

### Time Complexity

Your implementation repeatedly inserts characters at the beginning of `StringBuilder`, which can take time proportional to the current builder length.

Therefore, its running time is not necessarily linear in the decoded output size. A safe coarse upper bound for the implementation is **O(n + L²)**, since intermediate string construction and final reconstruction can repeatedly shift or copy characters.

### Space Complexity

The stack and intermediate builders store encoded or decoded characters. Their total size is bounded by the input and decoded output sizes.

```text
Auxiliary space: O(n + L)
Output space:    O(L)
```

The two-stack alternative avoids repeated front insertion, though its repetition loops still take time proportional to the decoded output being constructed.
