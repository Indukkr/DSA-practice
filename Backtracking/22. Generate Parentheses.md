# 🔗 Generate Parentheses — LeetCode #22

## 📌 Problem

Given `n` pairs of parentheses, generate all combinations of **well-formed parentheses**.

### Example

```text
Input:
n = 3

Output:
[
  "((()))",
  "(()())",
  "(())()",
  "()(())",
  "()()()"
]
```

For:

```text
n = 3
```

we need exactly:

```text
3 '('
3 ')'
```

---

# 🧠 Brute Force Thought Process

At every position, we could theoretically choose:

```text
'('
OR
')'
```

For `n = 3`, we need a string of length:

```text
2 × n = 6
```

So blindly generating all possible strings gives:

```text
2^6 = 64
```

possibilities.

But most of them are invalid.

For example:

```text
")))((("
"())())"
")()()("
```

are not valid parenthesis combinations.

Instead of generating invalid strings and checking them later, we can **prevent invalid choices while building the string**.

This leads to:

```text
Backtracking + Constraints
```

---

# 🚀 Approach — Backtracking With Open/Close Counts

We maintain two counters:

```java
open
close
```

### `open`

Number of `'('` already used.

### `close`

Number of `')'` already used.

At every step, we have two possible choices.

### Choice 1 — Add `'('`

We can add `'('` only when:

```java
open < n
```

because we can use at most `n` opening parentheses.

---

### Choice 2 — Add `')'`

We can add `')'` only when:

```java
close < open
```

because we cannot close more parentheses than we have opened.

This is the most important rule.

---

# 💡 Most Important Observation

The condition:

```java
if(close < open)
```

prevents invalid strings.

For example:

```text
current = "(()"
```

Counts:

```text
open = 2
close = 1
```

We can add:

```text
')'
```

because:

```text
close < open
1 < 2
```

But suppose:

```text
current = "())"
```

Counts:

```text
open = 1
close = 2
```

We cannot add another `')'`.

Why?

Because:

```text
close < open
2 < 1 → false
```

So the invalid branch is never explored.

---

# 🧠 The Two Rules

Memorize these two conditions:

### Add `(`

```java
if(open < n)
```

Meaning:

```text
We still have opening brackets available.
```

### Add `)`

```java
if(close < open)
```

Meaning:

```text
There is an unmatched '(' that can be closed.
```

These two conditions are the entire logic of the problem.

---

# 🌳 Recursion Tree

For:

```text
n = 3
```

The recursion starts:

```text
                         ""
                          |
                         "("
                       /     \
                     "(("     "()"
                      |
                    "((("
                   /     \
              "((()"     "((())"
                ...
```

More conceptually:

```text
                         ""
                          |
                         (
                       /   \
                     (       )
                   /           \
                 ((            ()
                /  \           / \
              (((  (()       ()(  () )
               ...
```

But invalid branches are **never created**.

For example:

```text
")"
```

is never generated at the root because:

```text
close = 0
open = 0

close < open
0 < 0 → false
```

This is the power of constraint-based backtracking.

Then:


# 🔧 Your Code

```java
class Solution {

    List<String> ansList = new ArrayList<>();

    public List<String> generateParenthesis(int n) {

        validParenthesis(n, 0, 0, "");

        return ansList;
    }

    public void validParenthesis(
        int n,
        int open,
        int close,
        String current
    ){

        if(close == n && open == n){
            ansList.add(current);
            return;
        }

        // Add '(' if we still have opening brackets available
        if(open < n){
            validParenthesis(
                n,
                open + 1,
                close,
                current + '('
            );
        }

        // Add ')' only if there is an unmatched '('
        if(close < open){
            validParenthesis(
                n,
                open,
                close + 1,
                current + ')'
            );
        }
    }
}
```

# 💡 Why Can We Always Add `(` When `open < n`?

Because adding an opening parenthesis cannot make the sequence invalid immediately.

For example:

```text
"("
"(("
"((("
```

All of these can potentially become valid later.

Therefore:

```java
if(open < n)
```

is enough.

---

# 💡 Why Can't We Always Add `)`?

This is the critical part.

Suppose:

```text
current = ""
```

If we add:

```text
")"
```

we get:

```text
")"
```

which is already invalid.

So we need to ensure that there is an unmatched opening parenthesis.

That condition is:

```java
close < open
```

Example:

```text
open = 2
close = 1
```

There is one unmatched `(`.

So we can add:

```text
)
```

# 🔄 Backtracking in This Problem

Unlike problems such as Subsets or Permutations, your implementation doesn't explicitly use:

```java
StringBuilder
```

with:

```java
append()
deleteCharAt()
```

because `String` is immutable.

Instead, you create a new string:

```java
current + '('
```

or:

```java
current + ')'
```

and pass it into the recursive call.

Conceptually, it is still:

```text
Choose
  ↓
Explore
  ↓
Return
  ↓
Try another choice
```

So this is still **backtracking**.

# 🆚 Why This Is Better Than Generate Everything First

The brute-force approach would be:

```text
Generate all 2^(2n) strings
        ↓
Check each string
        ↓
Keep only valid ones
```

Our approach is:

```text
Build the string
      ↓
Only make valid choices
      ↓
Never generate obviously invalid branches
```

For example, we never generate:

```text
")("
"))"
")(("
```

because the condition:

```java
close < open
```

prevents them.

This is called:

```text
Pruning
```


```text

   ↓

   ↓
```



# 🧩 Generic Backtracking Template

The structure is:

```java
void backtrack(state){

    if(solution){
        add answer;
        return;
    }

    if(choice1 is valid){
        make choice1;
        backtrack(new state);
    }

    if(choice2 is valid){
        make choice2;
        backtrack(new state);
    }
}
```

For this problem:

```java
if(open < n){
    // choose '('
}

if(close < open){
    // choose ')'
}
```

# ⚠️ Common Mistakes

## 1. Allowing `)` Without Checking `close < open`

Wrong:

```java
if(close < n){
    // add ')'
}
```

This can generate invalid strings such as:

```text
")("
```

Correct:

```java
if(close < open)
```

---

## 2. Allowing More Than `n` Opening Brackets

Wrong:

```java
validParenthesis(
    n,
    open + 1,
    close,
    current + '('
);
```

without:

```java
open < n
```

Correct:

```java
if(open < n)
```

---

## 3. Checking Only `open == n`

Reaching:

```text
open == n
```

does not mean the string is complete.

Example:

```text
"(("
```

for:

```text
n = 2
```

still needs:

```text
"))
```

So the complete condition is:

```java
open == n && close == n
```

---

## 4. Adding Answers Before the String Is Complete

Only add when:

```java
open == n && close == n
```

# ⏱️ Complexity

The number of valid combinations is the **n-th Catalan number**:

```text
Cₙ = (1 / (n + 1)) × (2n choose n)
```

Therefore, the number of valid outputs grows approximately as:

```text
O(4^n / n^(3/2))
```

Since every result has length:

```text
2n
```

the output itself requires:

```text
O(n × Cₙ)
```

space.

### Recursion Space

The maximum recursion depth is:

```text
2n
```

so the recursion stack uses:

```text
O(n)
```

auxiliary space.

### Important Interview Point

The exact complexity is output-sensitive because we must generate all valid strings.

A simple interview explanation is:

```text
Time:  O(n × Cₙ)
Space: O(n) auxiliary, excluding output
```

where `Cₙ` is the nth Catalan number.
