# 🧩 Sudoku Solver — LeetCode #37

## 📌 Problem

Write a program to solve a Sudoku puzzle by filling the empty cells.

A Sudoku board is a `9 x 9` grid.

Each empty cell is represented by `'.'`.

A valid Sudoku must satisfy:

1. Each **row** contains digits `1-9` without repetition.
2. Each **column** contains digits `1-9` without repetition.
3. Each **3 × 3 sub-grid** contains digits `1-9` without repetition.

The goal is to fill the entire board correctly.

---

# 🧠 Brute Force Thought Process

For every empty cell:

1. Try putting `1`.
2. Check whether it is valid.
3. Try putting `2`.
4. Check whether it is valid.
5. Continue until `9`.
6. If a choice leads to a dead end, undo it.
7. Try another number.

The important point is:

> We cannot simply place any number.  
> Every number must satisfy the Sudoku constraints.

This naturally leads to **Backtracking**.

---

# 🚀 Approach — Backtracking

We process the Sudoku board **cell by cell**.

The recursion keeps track of:

```text
row → current row
col → current column
```

For every cell:

### Case 1 — All rows completed

If:

```java
row == 9
```

then the complete board has been solved.

```java
if(row == 9) return true;
```

---

### Case 2 — Current row completed

If:

```java
col == 9
```

we move to the next row:

```java
if(col == 9)
    return solve(board,row+1,0);
```

So the traversal becomes:

```text
(0,0) → (0,1) → ... → (0,8)
                         ↓
                       (1,0)
                         ↓
                       (1,1)
                         ...
```

---

### Case 3 — Cell is already filled

If the cell already contains a number, we don't modify it.

```java
if(board[row][col] != '.')
    return solve(board,row,col+1);
```

We simply move to the next cell.

---

### Case 4 — Cell is empty

If the cell contains `'.'`, try every number from `1` to `9`.

```java
for(char num = '1'; num <= '9'; num++)
```

For every number:

1. Check whether it is safe.
2. Place it.
3. Explore the next cell.
4. If the choice fails, undo it.

This is the classic:

```text
CHOOSE
   ↓
EXPLORE
   ↓
UNDO
```

---

# 🔍 The Core Backtracking Logic

Your most important code is:

```java
if(isSafe(board,row,col,num)){

    // CHOOSE
    board[row][col] = num;

    // EXPLORE
    if(solve(board, row, col + 1))
        return true;

    // UNDO / BACKTRACK
    board[row][col] = '.';
}
```

Think of it as:

```text
Try number
    ↓
Is it safe?
    ↓
Yes
    ↓
Place number
    ↓
Solve remaining board
    ↓
      ┌───────────────┐
      │               │
    Success          Failure
      │               │
      ↓               ↓
 return true       remove number
                      ↓
                 try next number
```

# 🛡️ isSafe() — Three Conditions

Before placing a number, we have to check:

```text
1. Column
2. Row
3. 3 × 3 grid
```

---

## 1️⃣ Check Column

Your code:

```java
for(int i = 0; i < 9; i++){
    if(board[i][col] == num)
        return false;
}
```

This checks whether `num` already exists in the same column.

For example:

```text
        col
         ↓
. . . | . . . | . . .
. . 5 | . . . | . . .
. . . | . . . | . . .
```

If we are trying to place `5` in that column, it is invalid.

---

## 2️⃣ Check Row

Your code:

```java
for(int i = 0; i < 9; i++){
    if(board[row][i] == num)
        return false;
}
```

This checks whether `num` already exists in the same row.

For example:

```text
. . 5 . . . . . .
      ↑
      5 already exists
```

So we cannot place another `5` in that row.

---

## 3️⃣ Check 3 × 3 Grid

This is the most important part to understand.

First find the starting cell of the current 3 × 3 grid:

```java
int startRow = row / 3 * 3;
int startCol = col / 3 * 3;
```

### Why?

Suppose:

```text
row = 5
col = 7
```

Then:

```text
row / 3 = 5 / 3 = 1
1 * 3 = 3

col / 3 = 7 / 3 = 2
2 * 3 = 6
```

So:

```text
startRow = 3
startCol = 6
```

Therefore the 3 × 3 grid starts at:

```text
(3,6)
```

---

### 3 × 3 Grid Traversal

```java
for(int r = 0; r < 3; r++) {
    for(int c = 0; c < 3; c++) {

        if(board[startRow + r][startCol + c] == num)
            return false;
    }
}
```

It checks:

```text
(startRow, startCol)
(startRow, startCol + 1)
(startRow, startCol + 2)

(startRow + 1, startCol)
(startRow + 1, startCol + 1)
(startRow + 1, startCol + 2)

(startRow + 2, startCol)
(startRow + 2, startCol + 1)
(startRow + 2, startCol + 2)
```

# 🌳 Recursion Tree

The recursion tree is much larger than N-Queens because every empty cell can potentially try **9 different numbers**.

A simplified view:

```text
                    Start
                      |
                 Find empty cell
                      |
          ┌───────────┼───────────┐
          ↓           ↓           ↓
         Try 1       Try 2       Try 3
          |           |           |
       isSafe?      isSafe?      isSafe?
          |           |           |
         Yes         Yes          No
          |           |            X
          ↓           ↓
       Place 1      Place 2
          |           |
          ↓           ↓
      Next cell    Next cell
          |
    ┌─────┼─────┐
    ↓     ↓     ↓
   Try1  Try2  Try3
    |
  ...
    |
    └──────→ Dead End
               |
               ↓
          BACKTRACK
               |
               ↓
          Remove number
               |
               ↓
          Try next number
```

The important thing is:

> Each recursion level represents one empty cell.

Each branch represents:

> A candidate number chosen for that cell.

# 🔍 Small Example of Backtracking

Suppose an empty cell can accept:

```text
1, 2, 3
```

The algorithm tries:

```text
Cell
 |
 ├── 1
 │    |
 │    └── Next cells
 │          |
 │          └── Dead End ❌
 │
 │    Backtrack
 │
 ├── 2
 │    |
 │    └── Next cells
 │          |
 │          └── Dead End ❌
 │
 │    Backtrack
 │
 └── 3
      |
      └── Next cells
            |
            └── Solution ✅
```

When `1` fails:

```java
board[row][col] = '.';
```

removes `1`.

Then we try `2`.

If `2` also fails, remove it and try `3`.

This is exactly what **backtracking** means.

# 💡 Why Do We Return boolean?

Your `solve()` method returns:

```java
boolean
```

This is very useful.

If a valid solution is found:

```java
return true;
```

The `true` propagates all the way back through the recursion.

For example:

```text
Cell 20
   ↓
Cell 21
   ↓
Cell 22
   ↓
Solution found
   ↓
true
   ↓
true
   ↓
true
   ↓
true
```

Therefore we don't continue searching after finding the solution.

# 🔧 Your Code

```java
class Solution {
    public void solveSudoku(char[][] board) {
        solve(board, 0, 0);
    }

    public boolean solve(char[][] board, int row, int col) {

        // Row completed
        if (row == 9)
            return true;

        // Column completed for current row
        // Move to next row
        if (col == 9)
            return solve(board, row + 1, 0);

        // Cell is already filled
        if (board[row][col] != '.')
            return solve(board, row, col + 1);

        // Cell is empty
        for (char num = '1'; num <= '9'; num++) {

            if (isSafe(board, row, col, num)) {

                // CHOOSE
                board[row][col] = num;

                // EXPLORE
                if (solve(board, row, col + 1))
                    return true;

                // UNDO / BACKTRACK
                board[row][col] = '.';
            }
        }

        return false;
    }

    public boolean isSafe(char[][] board, int row, int col, char num) {

        // Check column
        for (int i = 0; i < 9; i++) {
            if (board[i][col] == num)
                return false;
        }

        // Check row
        for (int i = 0; i < 9; i++) {
            if (board[row][i] == num)
                return false;
        }

        // Check 3 x 3 grid
        int startRow = row / 3 * 3;
        int startCol = col / 3 * 3;

        for (int r = 0; r < 3; r++) {
            for (int c = 0; c < 3; c++) {

                if (board[startRow + r][startCol + c] == num)
                    return false;
            }
        }

        return true;
    }
}
```

# 🔧 Cleaner Version

One small cleanup is that this condition:

```java
if(board[row][col] == '.')
```

is unnecessary.

Why?

Because if the cell is not empty, we already returned here:

```java
if(board[row][col] != '.')
    return solve(board, row, col + 1);
```

Therefore, after that line, we already know:

```text
board[row][col] == '.'
```

So the code can be slightly cleaner:

```java
class Solution {

    public void solveSudoku(char[][] board) {
        solve(board, 0, 0);
    }

    private boolean solve(char[][] board, int row, int col) {

        // All rows completed
        if (row == 9)
            return true;

        // Current row completed
        if (col == 9)
            return solve(board, row + 1, 0);

        // Cell already filled
        if (board[row][col] != '.')
            return solve(board, row, col + 1);

        // Try digits 1 to 9
        for (char num = '1'; num <= '9'; num++) {

            if (isSafe(board, row, col, num)) {

                // CHOOSE
                board[row][col] = num;

                // EXPLORE
                if (solve(board, row, col + 1))
                    return true;

                // UNDO
                board[row][col] = '.';
            }
        }

        return false;
    }

    private boolean isSafe(char[][] board, int row, int col, char num) {

        // Check column
        for (int i = 0; i < 9; i++) {
            if (board[i][col] == num)
                return false;
        }

        // Check row
        for (int i = 0; i < 9; i++) {
            if (board[row][i] == num)
                return false;
        }

        // Find starting cell of 3 x 3 sub-grid
        int startRow = (row / 3) * 3;
        int startCol = (col / 3) * 3;

        // Check 3 x 3 sub-grid
        for (int r = 0; r < 3; r++) {
            for (int c = 0; c < 3; c++) {

                if (board[startRow + r][startCol + c] == num)
                    return false;
            }
        }

        return true;
    }
}
```

# ⚠️ Common Mistakes

### 1. Forgetting to undo

Wrong:

```java
board[row][col] = num;
solve(board, row, col + 1);
```

You must undo when the choice fails:

```java
board[row][col] = '.';
```

Otherwise the wrong number remains on the board.

---

### 2. Forgetting the 3 × 3 grid check

Checking only row and column is not enough.

Sudoku has three constraints:

```text
Row
Column
3 × 3 Grid
```

---

### 3. Moving to the wrong cell

After filling a cell:

```java
solve(board, row, col + 1);
```

After completing a row:

```java
solve(board, row + 1, 0);
```

---

### 4. Not returning true immediately

Once a solution is found:

```java
if(solve(board, row, col + 1))
    return true;
```

Without this, the algorithm may continue searching unnecessarily and potentially destroy the valid solution.

---

### 5. Confusing row and column checks

Remember:

```java
board[i][col]
```

means **column**.

```java
board[row][i]
```

means **row**.

This problem belongs to:

```text
Backtracking
    ↓

    ↓
Choose → Explore → Undo
```

The pattern is:

```text
1. Find an empty position
2. Try all possible choices
3. Check constraints
4. Choose
5. Recurse
6. Undo if unsuccessful
```

This same pattern appears in:

```text
Subsets

Combination Sum
Generate Parentheses
N-Queens

```

# 🔥 Backtracking Comparison

| Problem | Choice | Constraint |
|---|---|---|
| Subsets | Pick / Don't Pick | None |
| Permutations | Choose unused element | Element cannot repeat |
| Combination Sum | Choose candidate | Sum <= target |
| Generate Parentheses | `(` or `)` | Valid parentheses |
| N-Queens | Choose column | No queen attack |
| Word Search | Choose direction | Character + visited |
| Sudoku | Choose digit `1-9` | Row + Column + Grid |

The common pattern is always:

```text
CHOOSE
   ↓
EXPLORE
   ↓
UNDO
```

# ⏱️ Complexity

There are at most `81` cells.

For every empty cell, we can try up to `9` numbers.

The search space is exponential in the number of empty cells.

A simple upper-bound intuition is:

```text
O(9^E)
```

where `E` is the number of empty cells.

Each candidate also performs `isSafe()`, which checks:

```text
9 cells in column
+
9 cells in row
+
9 cells in grid
```

So each safety check is:

```text
O(27) = O(1)
```

because Sudoku has a fixed `9 × 9` size.

Therefore, for standard Sudoku:

```text
Time:  O(9^E)   worst-case search bound
Space: O(E)     recursion stack
```

The board itself uses:

```text
O(81) = O(1)
```

because the board size is fixed.
