# 📚 LeetCode 895 — Maximum Frequency Stack

## 1. Problem Statement

Design a stack-like data structure that supports two operations:

- `push(val)`: Push an integer `val` onto the stack.
- `pop()`: Remove and return the element that appears most frequently in the stack.

If multiple elements have the same maximum frequency, return the element that was pushed most recently among them.

### Example

**Input**
```text
push(5)
push(7)
push(5)
push(7)
push(4)
push(5)
pop()
pop()
pop()
pop()
```

**Output**
```text
5
7
5
4
```

### Why?

After all the push operations:

| Element | Frequency |
|---|---:|
| 5 | 3 |
| 7 | 2 |
| 4 | 1 |

1. First `pop()` returns `5` because it has the highest frequency.
2. Now `5` and `7` both have frequency `2`. The most recently pushed among them is `7`, so the next `pop()` returns `7`.
3. Now `5` and `7` both have frequency `1`. Since `5` was pushed more recently than `7` at that frequency level, the next `pop()` returns `5`.
4. Finally, `4` is returned.

---

## 2. Brute Force Approach

One possible approach is to maintain a normal stack and calculate the frequency of every element whenever `pop()` is called.

### Steps

1. Store all pushed elements in a stack or list.
2. When `pop()` is called, calculate the frequency of every element.
3. Find the element with the maximum frequency.
4. If multiple elements have the same frequency, choose the most recently pushed one.
5. Remove and return that element.

### Complexity

- `push()`: O(1)
- `pop()`: O(n²) in a straightforward implementation if frequencies are recalculated for every candidate.
- Space: O(n)

This is inefficient because we repeatedly calculate frequencies instead of maintaining the information as elements are pushed and popped.

---

## 3. Optimized Approach — Frequency Map + Frequency Groups

The key observation is that we need to consider **two things simultaneously**:

1. Which elements have the highest frequency?
2. Among elements with the same frequency, which one was pushed most recently?

A single frequency map cannot efficiently handle both requirements. Therefore, we use two maps and one variable.

### Data Structures

#### A. `frequency`

```java
Map<Integer, Integer> frequency;
```

Stores the current frequency of each element.

Example:

```text
frequency = {
    5: 3,
    7: 2,
    4: 1
}
```

#### B. `group`

```java
Map<Integer, Stack<Integer>> group;
```

Groups elements according to their frequency.

- `group.get(1)` stores elements that reached frequency 1.
- `group.get(2)` stores elements that reached frequency 2.
- `group.get(3)` stores elements that reached frequency 3.

Each group is a stack, so the most recently added element at that frequency is on top.

#### C. `maxFrequency`

```java
int maxFrequency;
```

Tracks the highest frequency currently present in the stack.

This allows `pop()` to directly access the group containing the element we need.

---

## 4. Understanding the Frequency Groups

Consider these operations:

```java
push(5);
push(7);
push(5);
push(7);
push(4);
push(5);
```

The frequency of each element changes as it is pushed.

| Operation | Element frequency after push | Stack updated |
|---|---:|---|
| `push(5)` | 5 → 1 | `group[1]` |
| `push(7)` | 7 → 1 | `group[1]` |
| `push(5)` | 5 → 2 | `group[2]` |
| `push(7)` | 7 → 2 | `group[2]` |
| `push(4)` | 4 → 1 | `group[1]` |
| `push(5)` | 5 → 3 | `group[3]` |

The frequency groups are now:

```text
group[1] = [5, 7, 4]
group[2] = [5, 7]
group[3] = [5]  ← maximum frequency
```

The rightmost element in each representation is the top of its stack.

Therefore:

```text
maxFrequency = 3
```

The first `pop()` retrieves `5` from `group[3]`.

After removing it, the frequency of `5` decreases to `2`. Since `group[3]` becomes empty, `maxFrequency` decreases to `2`.

The next `pop()` now operates on `group[2]`, returning `7` because it is on top.

**Important:** The groups store the history of elements reaching each frequency. They do not simply store each element once according to its current frequency.

---

## 5. Your Code

```java
class FreqStack {
    Map<Integer, Integer> frequency;
    Map<Integer, Stack<Integer>> group;
    int maxFrequency;

    public FreqStack() {
        frequency = new HashMap<>();
        group = new HashMap<>();
        maxFrequency = 0;
    }

    public void push(int val) {
        // Step 1: Get the new frequency of the element
        int f = frequency.getOrDefault(val, 0) + 1;

        // Step 2: Update the frequency map
        frequency.put(val, f);

        // Step 3: Update the maximum frequency
        maxFrequency = Math.max(f, maxFrequency);

        // Step 4: Create a stack for this frequency if needed
        if (!group.containsKey(f)) {
            group.put(f, new Stack<>());
        }

        // Step 5: Push the element into its frequency group
        group.get(f).push(val);
    }

    public int pop() {
        // Step 1: Pop from the maximum-frequency group
        int val = group.get(maxFrequency).pop();

        // Step 2: Decrease the element's frequency
        frequency.put(val, frequency.get(val) - 1);

        // Step 3: Reduce maxFrequency if this group becomes empty
        if (group.get(maxFrequency).isEmpty()) {
            maxFrequency--;
        }

        // Step 4: Return the removed element
        return val;
    }
}
```

## 6. Line-by-Line Explanation

### Constructor

```java
frequency = new HashMap<>();
group = new HashMap<>();
maxFrequency = 0;
```

Initially, there are no elements, so both maps are empty and the maximum frequency is zero.

### `push(int val)`

#### Step 1: Calculate the new frequency

```java
int f = frequency.getOrDefault(val, 0) + 1;
```

If the element does not exist, its frequency starts at zero. We add one because it is being pushed.

#### Step 2: Update the frequency

```java
frequency.put(val, f);
```

Store the element's new frequency.

#### Step 3: Update the maximum frequency

```java
maxFrequency = Math.max(f, maxFrequency);
```

If the new frequency exceeds the previous maximum, update `maxFrequency`.

#### Step 4: Create a frequency group when necessary

```java
if (!group.containsKey(f)) {
    group.put(f, new Stack<>());
}
```

A new frequency level may be reached for the first time, so we initialize its stack.

#### Step 5: Push into the corresponding group

```java
group.get(f).push(val);
```

The element is pushed onto the stack corresponding to its new frequency.

This also preserves recency: if two elements have the same frequency, the one most recently pushed into that frequency group will be on top.

### `pop()`

#### Step 1: Retrieve the most frequent, most recent element

```java
int val = group.get(maxFrequency).pop();
```

The top of the maximum-frequency stack is exactly the element required by the problem.

#### Step 2: Decrease its frequency

```java
frequency.put(val, frequency.get(val) - 1);
```

Since the element was removed once, its current frequency decreases by one.

#### Step 3: Reduce the maximum frequency if necessary

```java
if (group.get(maxFrequency).isEmpty()) {
    maxFrequency--;
}
```

If the current maximum-frequency group is empty, no element remains at that frequency. The maximum can therefore decrease by one.

#### Step 4: Return the removed element

```java
return val;
```

## 8. Important Observations

### Observation 1: Why do we need two maps?

The `frequency` map tells us how often an element currently occurs.

The `group` map tells us which element to remove when a particular frequency is the maximum, while preserving recency among elements at that frequency.

Each solves a different part of the problem.

### Observation 2: Why use a stack inside `group`?

The problem requires the most recently pushed element when frequencies are tied.

A stack provides LIFO ordering, so the latest element added to a frequency group is removed first.

### Observation 3: Why is `maxFrequency` necessary?

Without it, we would need to search for the highest non-empty frequency group during every `pop()`.

Maintaining `maxFrequency` lets us access the correct group directly.

### Observation 4: Why do we not remove an element from every lower-frequency group during `pop()`?

The group stacks record when elements reach particular frequency levels. Popping an element from the highest group exposes the previous frequency level naturally.

This history is exactly what makes the solution efficient.

---

## 9. Common Mistakes

1. **Using only a frequency map:** It does not track which tied element was pushed most recently.
2. **Using one ordinary stack only:** The top element might not have the maximum frequency.
3. **Forgetting to update `maxFrequency` during `push()`:** The maximum group could become incorrect.
4. **Forgetting to decrease the frequency after `pop()`:** Future operations would use incorrect counts.
5. **Forgetting to decrease `maxFrequency` when its group becomes empty:** A later `pop()` could try to use an empty maximum-frequency group.
6. **Removing the wrong element from a tied group:** Always pop from the stack associated with `maxFrequency`.

## 10. Time and Space Complexity

### Time Complexity

| Operation | Complexity | Reason |
|---|---|---|
| `push()` | O(1) | Map operations and stack push take O(1) average/amortized time. |
| `pop()` | O(1) | Stack pop, map updates, and the maximum-frequency check take O(1). |

Both operations run in **O(1) average time**.

### Space Complexity

**O(n)** auxiliary space, where `n` is the number of elements pushed and not yet popped, up to the total storage retained by the frequency-group stacks and maps.

---

## 11. Pattern Recognition

Recognize this pattern when a problem asks you to combine:

- Frequency counting
- Recency or ordering among ties
- Fast retrieval of a maximum-frequency element

The central idea is to maintain **frequency buckets, each with its own stack**, and track the current maximum frequency.

This avoids scanning all elements during `pop()`.

## 13. Interview Explanation

You can explain your approach like this:

"I use a frequency map to track the current count of each value, another map from frequency to a stack of values, and a variable to track the maximum frequency.

When I push a value, I increase its frequency, update the maximum if needed, and push the value into the stack for its new frequency.

When I pop, I remove the top value from the maximum-frequency stack and decrease its frequency. If that group becomes empty, I decrease the maximum frequency.

The frequency groups preserve recency among elements with equal frequencies, so both operations take O(1) average time."

## 14. Final Takeaway

The key insight is that **frequency alone is not enough; recency among equal-frequency elements also matters**.

Your solution handles both requirements using:

- `frequency` → tracks current element frequencies.
- `group` → maintains a stack for each frequency level.
- `maxFrequency` → identifies the group to pop from immediately.

This is an optimal approach for LeetCode 895, with O(1) average-time `push()` and `pop()` operations.
