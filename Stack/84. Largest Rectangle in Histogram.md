# 📚 LeetCode 84 — Largest Rectangle in Histogram

## 1. Problem Statement

You are given an array `heights`, where each element represents the height of a bar in a histogram. Every bar has a width of `1`.

Return the maximum rectangular area that can be formed using consecutive bars.

### Example

**Input**
```text
heights = [2, 1, 5, 6, 2, 3]
```

**Output**
```text
10
```

**Explanation**

The bars with heights `5` and `6` form a rectangle with:

- Height = `5`
- Width = `2`

Therefore:

`Area = 5 × 2 = 10`

---

## 2. Brute Force Approach

For every bar, consider it as the minimum-height bar of a rectangle.

1. Expand left while the bars are at least as tall as the current bar.
2. Expand right while the bars are at least as tall as the current bar.
3. Calculate the rectangle's width and area.
4. Update the maximum area.

### Complexity

- Time: O(n²)
- Space: O(1)

This approach is straightforward but can be too slow for large arrays.

---

## 3. Optimized Approach — Monotonic Increasing Stack

The key observation is:

**For every bar, we need to find the first smaller bar on its left and the first smaller bar on its right.**

These smaller bars determine how far a rectangle of the current bar's height can extend.

We use a stack to store **indices**, not heights.

### Why indices?

Indices help us calculate the rectangle's width after identifying the boundaries.

### Why a monotonic increasing stack?

We maintain indices whose corresponding heights are in non-decreasing order.

```text
heights[stack[0]] <= heights[stack[1]] <= ...
```

When the current height is smaller than the height at the top of the stack, we pop indices and calculate the maximum rectangle for each popped bar.

---

## 4. Your Code

```java
class Solution {
    public int largestRectangleArea(int[] heights) {

        int maxArea = 0;
        Stack<Integer> stack = new Stack<>();
        int n = heights.length;

        for (int i = 0; i <= n; i++) {

            // Use height 0 at the end to process remaining bars
            int currentHeight = (i == n) ? 0 : heights[i];

            while (!stack.isEmpty()
                    && heights[stack.peek()] > currentHeight) {

                int poppedIndex = stack.pop();

                int height = heights[poppedIndex];

                int width;

                if (stack.isEmpty()) {
                    width = i;
                } else {
                    width = i - stack.peek() - 1;
                }

                maxArea = Math.max(maxArea, width * height);
            }

            stack.push(i);
        }

        return maxArea;
    }
}
```

### Small improvement

Avoid pushing the sentinel index `n` onto the stack, because `heights[n]` does not exist.

```java
class Solution {
    public int largestRectangleArea(int[] heights) {

        int maxArea = 0;
        Stack<Integer> stack = new Stack<>();
        int n = heights.length;

        for (int i = 0; i <= n; i++) {

            int currentHeight = (i == n) ? 0 : heights[i];

            while (!stack.isEmpty()
                    && heights[stack.peek()] > currentHeight) {

                int height = heights[stack.pop()];

                int width = stack.isEmpty()
                        ? i
                        : i - stack.peek() - 1;

                maxArea = Math.max(maxArea, width * height);
            }

            if (i < n) {
                stack.push(i);
            }
        }

        return maxArea;
    }
}
```

Both versions calculate the correct maximum area. The second version simply avoids storing the out-of-range sentinel index.

## 5. Understanding the Width Formula

This is the most important part of the solution.

Suppose:

```text
heights = [2, 1, 5, 6, 2, 3]
```

Consider the bar with height `5` at index `2`.

When we reach index `4`, the current height is `2`, which is smaller than `5`. So we pop index `2`.

After popping:

- Current index `i = 4` is the first smaller bar on the right.
- The new stack top is index `1`, the previous smaller bar on the left.

The width is:

```text
width = right boundary - left boundary - 1
width = 4 - 1 - 1
width = 2
```

Therefore:

```text
area = height × width
area = 5 × 2
area = 10
```

### Case 1: Stack becomes empty after popping

```java
width = i;
```

There is no smaller bar on the left. The rectangle can extend from index `0` through index `i - 1`.

So its width is `i`.

### Case 2: Stack is not empty after popping

```java
width = i - stack.peek() - 1;
```

The stack top is the previous smaller bar on the left, and `i` is the first smaller bar on the right.

We subtract one from the distance because neither boundary bar can be included.

---

## 6. Why Do We Iterate Until `i <= n`?

Normally, array traversal uses:

```java
i < n
```

But your code uses:

```java
i <= n
```

At `i == n`, we set:

```java
int currentHeight = 0;
```

This is a **sentinel value**.

It forces all remaining positive-height bars to be popped and evaluated. Without this extra iteration, some bars might remain in the stack and their maximum possible areas might never be calculated.

For example:

```text
heights = [2, 4, 6]
```

The heights are increasing, so no bar is popped during normal traversal.

At the extra iteration, `currentHeight = 0` triggers the remaining pops, allowing the algorithm to calculate areas such as:

```text
height 6 → area 6 × 1 = 6
height 4 → area 4 × 2 = 8
height 2 → area 2 × 3 = 6
```

The maximum area is `8`.

**Important:** The sentinel is used as the current height for comparison; it does not need to be pushed onto the stack.

## 8. Common Mistakes

1. **Storing heights instead of indices:** Indices are needed to calculate widths.
2. **Using the wrong width formula:** Remember `i - stack.peek() - 1` when the stack is not empty.
3. **Forgetting the sentinel iteration:** Remaining bars may not be processed.
4. **Pushing the sentinel index:** `n` is outside the array; pushing it is unnecessary.
5. **Using `>=` without considering duplicates:** Using `>` as you did is valid. Equal-height bars may stay together until a smaller bar appears, and the width calculations still work.
6. **Calculating area using the current height:** The rectangle being evaluated has the height of the popped bar, not the current bar.

## 9. Time and Space Complexity

### Time Complexity: O(n)

Each index is pushed onto the stack once and popped at most once.

Although there is a `while` loop inside the `for` loop, the total number of stack operations across the entire algorithm is linear.

### Auxiliary Space Complexity: O(n)

In the worst case, the stack can hold all `n` indices, such as when the heights are strictly increasing.

## 11. Interview Explanation

"I maintain a monotonic increasing stack of indices. When I encounter a bar shorter than the bar at the stack's top, I pop that index and calculate the largest rectangle for the popped height. The current index provides the right boundary, while the new stack top provides the previous smaller boundary. I calculate the width and update the maximum area. Finally, I use a zero-height sentinel to process any bars remaining in the stack. Each index is pushed and popped at most once, giving O(n) time complexity."

---

## 12. Final Takeaway

The core idea is to calculate a rectangle **when its height can no longer extend further to the right**.

- Popped bar height → rectangle height.
- Current index → right smaller boundary.
- New stack top → left smaller boundary.
- Width → `i - stack.peek() - 1`, or `i` if the stack is empty.
- Sentinel height `0` → processes remaining bars.

Your approach is optimal at **O(n) time and O(n) auxiliary space**.
