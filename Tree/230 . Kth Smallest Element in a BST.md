# LeetCode 230 - Kth Smallest Element in a BST

## Pattern

BST + Inorder Traversal

---

## Key Observation

For a BST:

```text
Left < Root < Right
```

Therefore:

```text
Inorder Traversal => Sorted Order
```

Example:

```text
        5
       / \
      3   6
     / \
    2   4
   /
  1
```

Inorder:

```text
1, 2, 3, 4, 5, 6
```

The k-th element in this sorted sequence is the answer.

---

# Solution 1: Inorder + ArrayList

## Idea

1. Perform inorder traversal.
2. Store all elements in ArrayList.
3. Return list[k - 1].

```java
class Solution {

    ArrayList<Integer> ans = new ArrayList<>();

    public int kthSmallest(TreeNode root, int k) {

        inorder(root);

        return ans.get(k - 1);
    }

    private void inorder(TreeNode root){

        if(root == null)
            return;

        inorder(root.left);

        ans.add(root.val);

        inorder(root.right);
    }
}
```

### Time Complexity

Traversal visits every node exactly once.

```text
Traversal = O(N)
ArrayList insertion = O(1)
```

Total:

```text
Time = O(N)
```

### Space Complexity

ArrayList stores all nodes.

```text
Space = O(N)
```

### Interview Notes

✅ Easy to derive

✅ Uses BST property

❌ Stores all elements even though only k-th element is needed

# Solution 2: Inorder + PriorityQueue

## Idea

1. Traverse entire tree.
2. Insert all nodes into Min Heap.
3. Remove k elements.
4. Last removed element is the answer.

```java
class Solution {

    public int kthSmallest(TreeNode root, int k) {

        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        inorder(root, minHeap);

        int ans = 0;

        for(int i = 0; i < k; i++){
            ans = minHeap.poll();
        }

        return ans;
    }

    private void inorder(TreeNode root,
                         PriorityQueue<Integer> minHeap){

        if(root == null)
            return;

        inorder(root.left, minHeap);

        minHeap.offer(root.val);

        inorder(root.right, minHeap);
    }
}
```

### Why It Works

Min Heap always keeps the smallest element at the top.

```text
1st poll -> 1st smallest
2nd poll -> 2nd smallest
3rd poll -> 3rd smallest
...
kth poll -> kth smallest
```

The last value removed is the answer.

### Time Complexity

For N nodes:

```text
offer() = O(log N)
```

N insertions:

```text
N × log N
```

Removing k elements:

```text
k × log N
```

Total:

```text
Time = O(N log N)
```

### Space Complexity

Heap stores all nodes.

```text
Space = O(N)
```

---

## Interview Flag 🚩

### Why I Should NOT Choose PriorityQueue Here?

This solution is correct but not optimal.

Reason:

The problem explicitly says the input is a BST.

For a BST:

```text
Inorder Traversal => Sorted Order
```

A Min Heap is useful when data is unsorted and we need quick access to the smallest element.

However, BST already provides sorted order through inorder traversal.

Using a PriorityQueue means:

```text
Traverse Entire Tree
↓
Store Every Node in Heap
↓
Perform Heap Operations
```

which increases complexity unnecessarily.

### Complexity Comparison

| Approach | Time | Space |
|-----------|--------|--------|
| Inorder + ArrayList | O(N) | O(N) |
| Inorder + Counter | O(H) to O(N) | O(H) |
| PriorityQueue | O(N log N) | O(N) |

### Interviewer Expectation

When interviewer sees:

```text
BST + Kth Smallest
```

they expect:

```text
BST
↓
Inorder Traversal
↓
Sorted Order
```

Using PriorityQueue ignores the BST property and treats the input like a normal Binary Tree.

Therefore:

```text
✅ Correct

❌ Not Optimal
```

### When Would PriorityQueue Make Sense?

If the problem were:

```text
Kth Smallest Element in a Binary Tree
```

(not BST)

then PriorityQueue becomes a reasonable solution because no sorted property exists.

# Solution 3: Inorder + Counter (Interview Expected)

## Idea

Since inorder traversal already gives nodes in sorted order:

1. Traverse inorder.
2. Maintain count of visited nodes.
3. When count == k, current node is the answer.
4. No need to store all elements.

```java
class Solution {

    int count = 0;
    int answer = -1;

    public int kthSmallest(TreeNode root, int k) {

        inorder(root, k);

        return answer;
    }

    private void inorder(TreeNode root, int k){

        if(root == null || answer != -1)
            return;

        inorder(root.left, k);

        count++;

        if(count == k){
            answer = root.val;
            return;
        }

        inorder(root.right, k);
    }
}
```

### Why It Works

For BST:

```text
Inorder => Sorted Order
```

Example:

```text
1 -> count = 1
2 -> count = 2
3 -> count = 3
```

If:

```text
k = 3
```

then:

```text
answer = 3
```

Current node becomes the k-th smallest element.

### Time Complexity

Best Case:

```text
Answer found early
```

Approximately:

```text
O(H + k)
```

where:

```text
H = Height of Tree
```

Worst Case:

```text
O(N)
```

### Space Complexity

Only recursion stack is used.

```text
Space = O(H)
```

## Interview Notes

✅ Uses BST property

✅ No extra data structure

✅ No need to store all elements

✅ Expected interview solution

When you see:


