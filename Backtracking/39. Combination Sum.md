# 🔢 Combination Sum — LeetCode #39

## 📌 Problem

Given an array of **distinct integers** `candidates` and an integer `target`, return all unique combinations of candidates where the chosen numbers sum to `target`.

The same number may be chosen **unlimited times**.

The combinations can be returned in any order.

### Example

```text
Input:
candidates = [2,3,6,7]
target = 7

Output:
[
  [2,2,3],
  [7]
]
```

---

# 🧠 Brute Force Thought Process

We need to find all possible combinations whose sum is exactly:

```text
target
```

For every candidate, we have two choices:

```text
Include the current element
OR
Exclude the current element
```

But there is one important condition:

> An element can be selected **multiple times**.

For example:

```text
candidates = [2,3]
target = 7
```

We can choose:

```text
2
2
2
3
```

So:

```text
[2,2,3]
```

is valid.

Therefore, when we **include** an element, we should stay at the same index.

---

# 🚀 Approach — Pick / Don't Pick + Backtracking

At every index:

```text
             Current Element
              /            \
          INCLUDE          EXCLUDE
             |                |
       Stay at same        Move to
          index          next index
```

### Include

```java
getCombinations(candidates, index, ...)
```

Notice:

```text
index
```

does not change.

Why?

Because the same candidate can be used again.

---

### Exclude

```java
getCombinations(candidates, index + 1, ...)
```

We move to the next candidate because we have decided not to use the current candidate anymore.

---

# 🔍 Example

Consider:

```text
candidates = [2,3,6,7]
target = 7
```

Start:

```text
index = 0
sum = 0
list = []
```

Current element:

```text
2
```

### Include 2

```text
list = [2]
sum = 2
index = 0
```

We stay at:

```text
index = 0
```

because `2` can be reused.

Include `2` again:

```text
list = [2,2]
sum = 4
```

Include `2` again:

```text
list = [2,2,2]
sum = 6
```

Include `2` again:

```text
sum = 8
```

Now:

```text
sum > target
```

So we stop this branch.

---

# 🔄 Backtracking

After exploring:

```text
[2,2,2,2]
```

we remove the last `2`:

```java
list.removeLast();
```

Now:

```text
[2,2,2]
```

Then we explore the exclude branch.

Eventually we can choose:

```text
3
```

giving:

```text
[2,2,3]
```

and:

```text
2 + 2 + 3 = 7
```

So we add:

```text
[2,2,3]
```

to the answer.

# 🌳 Recursion Tree

For simplicity, consider:

```text
candidates = [2,3]
target = 7
```

The decision tree starts like:

```text
                         []
                    /          \
                 pick 2       skip 2
                   [2]          []
                 /    \
             pick 2   skip 2
              [2,2]    [2]
              /   \      /  \
          pick2 skip2 pick3 skip3
           ...    ...   ...   ...
```

The important thing is:

```text
Pick → SAME index
Skip → NEXT index
```

# 💡 Most Important Observation

This is the most important part of your solution:

```java
// Include
getCombinations(candidates, index, sum, target, list);

// Exclude
getCombinations(candidates, index + 1, sum, target, list);
```

### Why same index for include?

Because:

```text
Same candidate can be reused
```

### Why `index + 1` for exclude?

Because:

```text
We don't want to use this candidate anymore
```

This is the core idea of **Combination Sum I**.

---

# 🔥 Combination Sum Pattern

Remember:

```text
INCLUDE
   ↓
Same index
   ↓
Can use again

EXCLUDE
   ↓
index + 1
   ↓
Move to next candidate
```

This is an **Unbounded Knapsack-style** choice pattern.

# 🛑 Base Cases

Your solution has three important stopping conditions.

### 1. Index out of bounds

```java
if(index >= candidates.length)
    return;
```

There are no more candidates to consider.

---

### 2. Sum exceeds target

```java
if(sum > target)
    return;
```

Since all candidates are positive, once:

```text
sum > target
```

we can never come back down to `target`.

Therefore this branch can stop immediately.

---

### 3. Target reached

```java
if(sum == target){
    ansList.add(new ArrayList<>(list));
    return;
}
```

We found a valid combination.

We add a **copy** of the current list.

---

# 🔧 Your Code

```java
class Solution {

    List<List<Integer>> ansList = new ArrayList<>();

    public List<List<Integer>> combinationSum(
        int[] candidates,
        int target
    ) {

        getCombinations(
            candidates,
            0,
            0,
            target,
            new ArrayList<>()
        );

        return ansList;
    }

    public void getCombinations(
        int[] candidates,
        int index,
        int sum,
        int target,
        List<Integer> list
    ){

        if(index >= candidates.length)
            return;

        if(sum > target)
            return;

        if(sum == target){
            ansList.add(new ArrayList<>(list));
            return;
        }

        list.add(candidates[index]);
        sum = sum + candidates[index];

        // Include the element
        getCombinations(
            candidates,
            index,
            sum,
            target,
            list
        );

        sum -= candidates[index];
        list.removeLast();

        // Exclude the current index element
        getCombinations(
            candidates,
            index + 1,
            sum,
            target,
            list
        );
    }
}
```

# 🔧 Cleaner Version

Your code works, but one thing can be simplified.

Instead of maintaining:

```java
sum
```

we can maintain the remaining target.

For example:

```text
target = 7

Pick 2
remaining = 5

Pick 2
remaining = 3

Pick 3
remaining = 0
```

Then the base cases become:

```java
if(target == 0)
```

and:

```java
if(target < 0)
```

A cleaner version is:

```java
class Solution {

    List<List<Integer>> ans = new ArrayList<>();

    public List<List<Integer>> combinationSum(
        int[] candidates,
        int target
    ) {

        backtrack(candidates, 0, target, new ArrayList<>());

        return ans;
    }

    private void backtrack(
        int[] candidates,
        int index,
        int target,
        List<Integer> current
    ){

        if(target == 0){
            ans.add(new ArrayList<>(current));
            return;
        }

        if(target < 0 || index == candidates.length)
            return;

        // Include current candidate
        current.add(candidates[index]);

        backtrack(
            candidates,
            index,
            target - candidates[index],
            current
        );

        // Backtrack
        current.remove(current.size() - 1);

        // Exclude current candidate
        backtrack(
            candidates,
            index + 1,
            target,
            current
        );
    }
}
```

### Your approach and this version are logically the same.

Your version:

```text
sum increases
```

Cleaner version:

```text
remaining target decreases
```

Both work.

# 💡 Why Does Include Use the Same Index?

Suppose:

```text
candidates = [2,3,6,7]
```

and we choose:

```text
2
```

We are allowed to choose `2` again.

Therefore:

```java
getCombinations(candidates, index, ...)
```

not:

```java
getCombinations(candidates, index + 1, ...)
```

If we used `index + 1` after picking `2`, we would never be able to generate:

```text
[2,2,3]
```

# 🆚 Combination Sum I vs Combination Sum II

This is an extremely important interview distinction.

## Combination Sum I — #39

Same element can be reused.

```text
Pick → SAME index
```

Example:

```text
[2,2,3]
```

---

## Combination Sum II — #40

Each element can be used at most once.

```text
Pick → NEXT index
```

and duplicate candidates require additional duplicate handling.

So:

```text
#39:
Include → index
Exclude → index + 1

#40:
Include → index + 1
Exclude → index + 1
+
Skip duplicates
```

# ⚠️ Common Mistakes

## 1. Moving to `index + 1` After Include

Wrong:

```java
getCombinations(
    candidates,
    index + 1,
    ...
);
```

for the include case.

That would prevent reuse.

Correct:

```java
getCombinations(
    candidates,
    index,
    ...
);
```

---

## 2. Forgetting to Backtrack

Wrong:

```java
list.add(candidates[index]);

getCombinations(...);

// Missing remove
```

Correct:

```java
list.add(candidates[index]);

getCombinations(...);

list.removeLast();
```

---

## 3. Forgetting `sum -= candidates[index]`

In your implementation, you explicitly maintain `sum`.

So after returning from the include branch:

```java
sum -= candidates[index];
```

is needed before exploring the exclude branch.

Otherwise the exclude branch would receive the wrong sum.

---

## 4. Adding the Same List Reference

Wrong:

```java
ansList.add(list);
```

Correct:

```java
ansList.add(new ArrayList<>(list));
```

Because the list is modified during backtracking.

---

## 5. Not Stopping When `sum > target`

Since all candidates are positive:

```text
sum > target
```

means the current branch cannot become valid.

So:

```java
if(sum > target)
    return;
```

is useful pruning.

# 🎯 Interview Explanation

> "I use backtracking with an include/exclude decision. For the include branch, I keep the same index because a candidate can be selected unlimited times. For the exclude branch, I move to the next index because I don't want to use the current candidate anymore. I stop when the sum reaches the target and backtrack whenever the sum exceeds the target."

# 🧩 Generic Template

For an unbounded combination problem:

```java
void backtrack(int index, List<Integer> current, int remaining){

    if(remaining == 0){
        // valid combination
        return;
    }

    if(index == nums.length || remaining < 0){
        return;
    }

    // Pick
    current.add(nums[index]);

    backtrack(
        index,
        current,
        remaining - nums[index]
    );

    // Undo
    current.remove(current.size() - 1);

    // Don't pick
    backtrack(
        index + 1,
        current,
        remaining
    );
}
```

The important line is:

```java
backtrack(index, ...)
```

for the pick branch.

# ⏱️ Complexity

Let:

```text
n = number of candidates
T = target
```

The exact number of combinations explored depends on the candidate values and target.

Because candidates can be reused, the recursion depth can be up to roughly:

```text
T / min(candidate)
```

The search is exponential in the worst case.

A commonly used upper-bound style description is:

```text
O(n^(T / minCandidate))
```

for the search tree, with additional cost for copying each valid combination.

### Space

Recursion depth can be:

```text
O(T / minCandidate)
```

The output itself can be large and depends on the number and sizes of valid combinations.
