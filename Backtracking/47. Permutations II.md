# 🔢 Permutations II — LeetCode #47

## 📌 Problem

Given an integer array `nums` that may contain **duplicates**, return all possible unique permutations.

The solution must **not contain duplicate permutations**.

### Example

```text
Input:
nums = [1,1,2]

Output:
[
  [1,1,2],
  [1,2,1],
  [2,1,1]
]
```

Notice that because `1` appears twice, we should not generate duplicate permutations such as:

```text
[1,1,2]
[1,1,2]
[1,2,1]
...
```

---

# 🧠 Brute Force Thought Process

A natural first thought is to use the same approach as **LeetCode #46 — Permutations**.

For every position:

```text
Choose any unused element
        ↓
Explore
        ↓
Backtrack
```

But there is a problem.

Consider:

```text
nums = [1,1,2]
```

The two `1`s have the same value.

If we treat them independently, we can generate the same permutation multiple times.

For example:

```text
First 1 → Second 1 → 2
Second 1 → First 1 → 2
```

Both produce:

```text
[1,1,2]
```

So we need a way to **skip duplicate choices at the same recursion level**.

---

# 🚀 Approach — Sorting + Backtracking + Duplicate Skipping

The solution has three important parts:

```text
1. Sort the array
2. Use visited[] to track used elements
3. Skip duplicate elements at the same recursion level
```

---

# 1️⃣ Sort the Array

First:

```java
Arrays.sort(nums);
```

For example:

```text
[2,1,1]
```

becomes:

```text
[1,1,2]
```

Sorting places duplicate values next to each other.

This allows us to easily detect:

```java
nums[i] == nums[i-1]
```

---

# 2️⃣ Track Used Elements

We use:

```java
boolean[] visited
```

where:

```text
visited[i] = true
```

means:

```text
nums[i] is already used in the current permutation
```

For example:

```text
nums = [1,1,2]

visited = [true,false,false]
```

means the first `1` is currently being used.

---

# 3️⃣ Skip Duplicate Choices

This is the most important line in your solution:

```java
if(visited[i] ||
   (!visited[i] && i > 0 &&
    nums[i] == nums[i-1] &&
    !visited[i-1]))
    continue;
```

The duplicate condition is:

```java
i > 0 &&
nums[i] == nums[i-1] &&
!visited[i-1]
```

Meaning:

> If the current number is the same as the previous number, and the previous identical number has NOT been used at this recursion level, skip the current number.

This prevents duplicate permutations.

---

# 💡 The Most Important Rule

Remember this:

```text
Same value
+
Same recursion level
+
Previous duplicate not used
=
SKIP
```

In short:

```text
if(nums[i] == nums[i-1] && !visited[i-1])
    continue;
```

This is the key rule for **Permutations II**.

---

# 🔍 Example

Consider:

```text
nums = [1,1,2]
```

After sorting:

```text
[1,1,2]
```

Initially:

```text
list = []
visited = [false,false,false]
```

At the first recursion level:

```text
i = 0 → choose first 1
i = 1 → choose second 1
i = 2 → choose 2
```

We need to avoid choosing the second `1` first because the first `1` has the same value and hasn't been used yet.

---

# 🔍 Why `!visited[i-1]`?

This is the most confusing part of the problem.

Suppose:

```text
nums = [1,1,2]
```

### Case 1 — Previous duplicate is NOT used

```text
visited = [false,false,false]
```

At:

```text
i = 1
```

we have:

```text
nums[1] == nums[0]
```

and:

```text
visited[0] == false
```

Therefore:

```java
!visited[i-1] == true
```

So we skip `nums[1]`.

Why?

Because choosing the second `1` before the first `1` would create a duplicate branch.

---

### Case 2 — Previous duplicate IS used

Suppose:

```text
list = [1]
```

and:

```text
visited = [true,false,false]
```

Now at:

```text
i = 1
```

we have:

```text
nums[1] == nums[0]
```

but:

```text
visited[0] == true
```

Therefore:

```java
!visited[i-1] == false
```

So we **do not skip**.

We can use the second `1`.

This is necessary to generate:

```text
[1,1,2]
```

---

# 🧠 The Key Difference

This condition:

```java
!visited[i-1]
```

means:

> "The previous identical element has not been used in the current permutation path."

If it has already been used:

```text
Previous duplicate = used
```

then the current duplicate is allowed.

If it has not been used:

```text
Previous duplicate = unused
```

then the current duplicate is skipped at this level.

---

# 🌳 Recursion Idea

For:

```text
nums = [1,1,2]
```

we want the recursion to conceptually behave like:

```text
                         []
                    /          \
                   1            2
                /     \
              1         2
             /           \
            2             1
```

Result:

```text
[1,1,2]
[1,2,1]
[2,1,1]
```

The duplicate `1` branches that would produce identical permutations are skipped.

```text
  ↓

  ↓
```

# 🔧 Your Code

```java
class Solution {

    List<List<Integer>> ans = new ArrayList<>();

    public List<List<Integer>> permuteUnique(int[] nums) {

        Arrays.sort(nums);

        helper(
            nums,
            new ArrayList<>(),
            new boolean[nums.length]
        );

        return ans;
    }

    public void helper(
        int[] nums,
        List<Integer> list,
        boolean[] visited
    ){

        if(list.size() == nums.length)
        {
            ans.add(new ArrayList<>(list));
            return;
        }

        for(int i = 0; i < nums.length; i++){

            if(
                visited[i] ||
                (
                    !visited[i] &&
                    i > 0 &&
                    nums[i] == nums[i-1] &&
                    !visited[i-1]
                )
            )
                continue;

            visited[i] = true;
            list.add(nums[i]);

            helper(nums, list, visited);

            list.removeLast();
            visited[i] = false;
        }
    }
}
```

# 🔧 Cleaner Version

Your duplicate condition can be simplified.

Since the first condition already handles:

```java
visited[i]
```

we don't need to check:

```java
!visited[i]
```

again.

So this:

```java
if(visited[i] ||
   (!visited[i] &&
    i > 0 &&
    nums[i] == nums[i-1] &&
    !visited[i-1]))
```

can be written as:

```java
if(visited[i] ||
   (i > 0 &&
    nums[i] == nums[i-1] &&
    !visited[i-1]))
```

Complete cleaner version:

```java
class Solution {

    List<List<Integer>> ans = new ArrayList<>();

    public List<List<Integer>> permuteUnique(int[] nums) {

        Arrays.sort(nums);

        helper(nums, new ArrayList<>(), new boolean[nums.length]);

        return ans;
    }

    private void helper(
        int[] nums,
        List<Integer> current,
        boolean[] visited
    ){

        if(current.size() == nums.length){
            ans.add(new ArrayList<>(current));
            return;
        }

        for(int i = 0; i < nums.length; i++){

            if(visited[i])
                continue;

            if(i > 0 &&
               nums[i] == nums[i-1] &&
               !visited[i-1])
                continue;

            visited[i] = true;
            current.add(nums[i]);

            helper(nums, current, visited);

            current.remove(current.size() - 1);
            visited[i] = false;
        }
    }
}
```

This is the same logic as your solution, just easier to read.

# 💡 Important Observation — Same Level vs Different Level

This is the most important concept in the entire problem.

We only skip duplicates when they are competing as **choices at the same recursion level**.

For example:

```text
[]
```

At this level:

```text
1
1
2
```

The two `1`s are duplicate choices.

So we skip the second one.

But after choosing the first `1`:

```text
[1]
```

we are at a different recursion level.

Now choosing the second `1` is valid:

```text
[1,1]
```

Therefore:

```text
Same level → skip duplicate
Different level → duplicate may be used
```

---

# 🔥 The Golden Rule

Memorize this condition:

```java
if(i > 0 &&
   nums[i] == nums[i-1] &&
   !visited[i-1])
    continue;
```

Meaning:

```text
Current == Previous
        +
Previous not used in current path
        ↓
Skip current
```

This prevents duplicate branches while still allowing duplicate values to appear in the same permutation.

# ⚠️ Common Mistakes

## 1. Forgetting to Sort

Wrong:

```java
helper(nums, ...);
```

without:

```java
Arrays.sort(nums);
```

The duplicate-skipping condition depends on duplicates being adjacent.

Correct:

```java
Arrays.sort(nums);
```

---

## 2. Using Only `nums[i] == nums[i-1]`

This is too aggressive:

```java
if(i > 0 && nums[i] == nums[i-1])
    continue;
```

This would incorrectly prevent:

```text
[1,1,2]
```

from being generated.

We need:

```java
!visited[i-1]
```

as well.

---

## 3. Using `visited[i-1]` Instead of `!visited[i-1]`

Wrong:

```java
nums[i] == nums[i-1] && visited[i-1]
```

That would skip the current duplicate when the previous duplicate is already part of the current path.

But:

```text
[1,1]
```

is a valid part of the permutation.

So we need:

```java
!visited[i-1]
```

---

## 4. Forgetting to Backtrack

Wrong:

```java
visited[i] = true;
list.add(nums[i]);

helper(...);

// Missing undo
```

Correct:

```java
list.remove(list.size() - 1);
visited[i] = false;
```

Both pieces are required.

---

## 5. Adding the Same List Reference

Wrong:

```java
ans.add(list);
```

Correct:

```java
ans.add(new ArrayList<>(list));
```

Because the current list changes during backtracking.

# 🎯 Interview Explanation

> "This is a variation of Permutations where duplicate values are allowed. I first sort the array so equal values are adjacent. I then use backtracking with a visited array to track which indices are already used in the current permutation. To avoid duplicate permutations, when the current value equals the previous value, I skip it if the previous identical element has not been used in the current path. This ensures that duplicate values are not chosen as equivalent options at the same recursion level, while still allowing both duplicate values to appear in the same permutation."

This problem combines three concepts:


The general pattern is:

```text

    if already used:

    if duplicate choice at same level:
        skip

    choose

    explore

    undo
```

# ⏱️ Complexity

Let:

```text
n = nums.length
```

There can be at most:

```text
n!
```

permutations.

For every complete permutation, we copy `n` elements:

```text
O(n × n!)
```

### Sorting

```text
O(n log n)
```

### Backtracking

Worst case:

```text
O(n × n!)
```

Therefore overall:

```text
O(n × n!)
```

The sorting cost is smaller than the permutation generation cost for the usual asymptotic analysis.

### Space

Visited array:

```text
O(n)
```

Recursion stack:

```text
O(n)
```

Current permutation:

```text
O(n)
```

Output:

```text
O(n × n!)
```

Therefore auxiliary space excluding output:

```text
O(n)
```
