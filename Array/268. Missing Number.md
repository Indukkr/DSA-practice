# 🔢 Missing Number — LeetCode #268

## 📌 Problem

Given an array `nums` containing `n` distinct numbers in the range:

```text
[0, n]
```

return the only number in the range that is missing from the array.

### Example

```text
Input:

nums = [3, 0, 1]

Output:

2
```

Because the numbers from `0` to `3` should be:

```text
0  1  2  3
```

but `2` is missing.

---

# 🧠 Brute Force Thought Process

The first thought is:

> "I need to find which number from `0` to `n` is missing."

One simple approach is to check every number from:

```text
0 → n
```

and search whether that number exists in the array.

For example:

```text
nums = [3, 0, 1]

Check 0 → present
Check 1 → present
Check 2 → missing
```

But if we search the array for every number, the time complexity becomes:

```text
O(n²)
```

We can do better.

---

# 🚀 Approach — Sorting

Since the numbers are from:

```text
0 → n
```

after sorting, the correct array should look like:

```text
0  1  2  3  4  ...
```

Therefore, we can compare:

```text
nums[i] with i
```

If:

```java
nums[i] != i
```

then `i` is the missing number.

---

# 🔍 Example

Consider:

```text
nums = [3, 0, 1]
```

After sorting:

```text
[0, 1, 3]
```

Now compare each index with its value:

```text
Index:  0  1  2
Value:  0  1  3
        ✓  ✓  ✗
```

At:

```text
i = 2
```

we have:

```text
nums[2] = 3
```

but:

```text
i = 2
```

Therefore:

```text
2 is missing
```

---

# 💡 Important Observation

After sorting:

```text
nums[i] == i
```

should be true for every element **before the missing number**.

Example:

```text
[0, 1, 2, 4, 5]
```

Comparison:

```text
Index:  0  1  2  3  4
Value:  0  1  2  4  5
        ✓  ✓  ✓  ✗
```

At the first mismatch:

```text
nums[i] != i
```

we know:

```text
i = missing number
```

---

# 🔧 Your Approach

Your solution first sorts the array:

```java
Arrays.sort(nums);
```

Then you compare every value with its expected index:

```java
if(nums[i] != i)
    return i;
```

If there is no mismatch, then the missing number must be:

```text
nums.length
```

because the range is:

```text
0 → n
```

and there are only `n` elements in the array.

---

# 🔧 Your Code

```java
class Solution {
    public int missingNumber(int[] nums) {

        Arrays.sort(nums);

        for(int i = 0; i < nums.length; i++){

            if(nums[i] != i)
                return i;
        }

        return nums.length;
    }
}
```

---

# 🧠 Why `return nums.length`?

This is an important edge case.

Suppose:

```text
nums = [0, 1, 2, 3]
```

Here:

```text
nums.length = 4
```

The complete range should be:

```text
0  1  2  3  4
```

But `4` is missing.

During the loop:

```text
nums[0] == 0
nums[1] == 1
nums[2] == 2
nums[3] == 3
```

There is no mismatch.

Therefore:

```text
missing number = n
```

So:

```java
return nums.length;
```

# 🔄 Optimized Approach

Your solution is correct, but sorting makes the complexity:

```text
O(n log n)
```

There is a better solution using the **XOR pattern**.

The important property is:

```text
x ^ x = 0
```

and:

```text
x ^ 0 = x
```

If we XOR all numbers from:

```text
0 → n
```

and all numbers present in the array, every existing number cancels out.

The only number left is the missing number.

---

# 🔧 XOR Version

```java
class Solution {
    public int missingNumber(int[] nums) {

        int xor = nums.length;

        for(int i = 0; i < nums.length; i++){

            xor = xor ^ i ^ nums[i];
        }

        return xor;
    }
}
```

---

# 🧠 XOR Example

Consider:

```text
nums = [3, 0, 1]
```

Here:

```text
n = 3
```

Numbers we expect:

```text
0 1 2 3
```

Numbers present:

```text
3 0 1
```

XOR everything:

```text
0 ^ 1 ^ 2 ^ 3
^
3 ^ 0 ^ 1
```

Same numbers cancel:

```text
0 ^ 0 = 0
1 ^ 1 = 0
3 ^ 3 = 0
```

Only:

```text
2
```

remains.

Therefore:

```text
Missing Number = 2
```

---

# 🔄 Sorting vs XOR

| Approach | Time | Extra Space |
|---|---:|---:|
| Brute Force Search | O(n²) | O(1) |
| Sorting | O(n log n) | O(1)* |
| XOR | O(n) | O(1) |

`*` The exact auxiliary space behavior of `Arrays.sort()` depends on the Java implementation, but for primitive `int[]`, it is in-place with constant auxiliary stack space.

For interviews, the **XOR solution is the optimal O(n) time / O(1) extra-space approach**.

# ⚠️ Common Mistakes

### 1. Forgetting that the range is `0 → n`

If:

```text
nums.length = n
```

the possible numbers are:

```text
0, 1, 2, ..., n
```

There are `n + 1` possible numbers but only `n` elements in the array.

---

### 2. Forgetting the `n` case

If every index matches:

```text
nums[i] == i
```

the answer is not `-1`.

It is:

```java
nums.length
```

---

### 3. Returning `nums[i]` instead of `i`

After sorting:

```text
[0, 1, 3]
```

At index:

```text
i = 2
```

we have:

```text
nums[i] = 3
```

The missing number is:

```text
i = 2
```

So:

```java
return i;
```
