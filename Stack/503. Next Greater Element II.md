# 🔄 Next Greater Element II — LeetCode #503

## 📌 Problem

Given a circular integer array `nums`, return an array `ans` where:

`ans[i]` is the next greater element of `nums[i]`.

The next greater element is the first element strictly greater than the current element when moving to the right.

Because the array is circular, after reaching the last element, we continue searching from the beginning.

If no greater element exists, return `-1`.

### Example

```text
Input:
nums = [1,2,1]

Output:
[2,-1,2]
```

Explanation:

- For `1` at index `0`, the next greater element is `2`.
- For `2` at index `1`, no greater element exists, so the answer is `-1`.
- For `1` at index `2`, we wrap around to the beginning and find `2`.

---

# 🧠 Brute Force Thought Process

For every element:

1. Start searching from the next index.
2. Continue moving to the right.
3. If the end of the array is reached, wrap around to index `0`.
4. Stop when a strictly greater element is found.
5. If we return to the original element without finding a greater one, store `-1`.

### Example

```text
nums = [1,2,1]

For index 0:
1 → 2 is greater
Answer = 2

For index 1:
2 → 1 → 1
No greater element
Answer = -1

For index 2:
1 → wrap around → 1 → 2
Answer = 2
```

### Brute Force Complexity

For every element, we may examine up to `n - 1` other elements.

```text
Time:  O(n²)
Space: O(1) auxiliary space
```

The output array requires an additional `O(n)` space.

We can optimize this using a **Monotonic Stack**.

---

# 🚀 Optimized Approach — Monotonic Stack + Circular Traversal

The key observation is:

> We can simulate a circular array by traversing the array twice.

Instead of creating a second copy of the array, use:

```java
nums[i % n]
```

The modulo operator maps an index back into the original array.

For example, if:

```text
nums = [1,2,1]
n = 3
```

Then:

| `i` | `i % n` | Actual index |
|---:|---:|---:|
| 5 | 2 | 2 |
| 4 | 1 | 1 |
| 3 | 0 | 0 |
| 2 | 2 | 2 |
| 1 | 1 | 1 |
| 0 | 0 | 0 |

The traversal visits:

```text
2 → 1 → 0 → 2 → 1 → 0
```

We process indices from right to left, simulating two passes over the circular array.

---

# 💡 Why Traverse Twice?

In a normal array, elements cannot find a greater element before their index.

In a circular array, they can.

For example:

```text
nums = [5,1,3]
```

For the element `3`:

```text
3 → wrap around → 5
```

The next greater element is `5`.

A single right-to-left pass cannot initially use elements at the beginning of the array as candidates for elements near the end.

The second simulated pass makes those candidates available.

We don't need to calculate answers during both passes.

```java
if(i < n)
```

ensures that we store answers only during the actual pass over indices `n - 1` through `0`.

---

# 🔥 Your Three Key Operations

## 1. Traverse Twice

Your code:

```java
for(int i = n * 2 - 1; i >= 0; i--)
```

This processes `2n` positions in reverse order.

The simulated array positions are:

```text
2n-1, 2n-2, ..., n, n-1, ..., 1, 0
```

Using modulo maps them back to valid indices.

## 2. Remove Smaller or Equal Elements

```java
while(!stack.isEmpty() && stack.peek() <= nums[i % n])
    stack.pop();
```

The stack stores **values**, not indices.

We remove every value less than or equal to the current value because it cannot be the next strictly greater element.

After popping:

- If the stack is empty, the answer is `-1`.
- Otherwise, the top is the next greater candidate.

## 3. Store Answers Only in the Second Pass

```java
if(i < n) {
    ans[i] = stack.isEmpty() ? -1 : stack.peek();
}
```

The first simulated pass prepares useful candidates.

The second pass calculates the actual answers.

Finally:

```java
stack.push(nums[i % n]);
```

The current value becomes a candidate for elements to its left.

# 🌳 Stack Evolution

For:

```text
nums = [1,2,1]
```

### First simulated pass

Process index `2`, value `1`:

```text
Stack: [1]
```

Process index `1`, value `2`:

```text
Pop 1 because 1 <= 2

Stack: []
Push 2

Stack: [2]
```

Process index `0`, value `1`:

```text
1 < 2

Stack: [1,2]
```

The stack now contains useful candidates from the simulated traversal.

### Second pass

Process index `2`, value `1`:

```text
Top = 2

ans[2] = 2
```

Process index `1`, value `2`:

```text
Pop 1
Pop 2

Stack becomes empty

ans[1] = -1
```

Process index `0`, value `1`:

```text
Top = 2

ans[0] = 2
```

Final result:

```text
[2,-1,2]
```

# 🔧 Your Code

```java
class Solution {
    public int[] nextGreaterElements(int[] nums) {

        int[] ans = new int[nums.length];
        Stack<Integer> stack = new Stack<>();
        int n = nums.length;

        for(int i = n * 2 - 1; i >= 0; i--) {

            while(!stack.isEmpty() && stack.peek() <= nums[i % n])
                stack.pop();

            if(i < n) {
                ans[i] = stack.isEmpty() ? -1 : stack.peek();
            }

            stack.push(nums[i % n]);
        }

        return ans;
    }
}
```

Your solution is correct and uses the standard monotonic stack approach.

# 💡 Important Observations

## 1. Modulo simulates circular traversal

```java
nums[i % n]
```

maps an index in the simulated doubled traversal to the original array.

## 2. The stack stores values

Unlike Daily Temperatures (#739), where you need the distance between indices, here you only need the next greater value.

Therefore, storing values is sufficient.

## 3. The comparison must be strict

```java
stack.peek() <= nums[i % n]
```

Equal values are not greater, so they must be removed.

## 4. The second pass calculates the answers

```java
if(i < n)
```

prevents the first simulated pass from writing answers to the wrong positions.

## 5. An empty stack means no greater element

```java
ans[i] = -1;
```

# ⚠️ Common Mistakes

### Mistake 1 — Traversing only once

A single pass misses possible greater elements that wrap around to the beginning.

### Mistake 2 — Forgetting modulo

Wrong:

```java
nums[i]
```

This would go out of bounds when `i >= n`.

Correct:

```java
nums[i % n]
```
