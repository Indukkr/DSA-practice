# LeetCode 236 - Lowest Common Ancestor of a Binary Tree

## Pattern

Tree + DFS + Postorder Traversal

---

## Key Observation

Unlike BST, a normal Binary Tree has:

```text
No ordering property
```

We cannot decide whether to move left or right.

Therefore:

```text
Need to search both subtrees.
```

---

## What is Lowest Common Ancestor?

The Lowest Common Ancestor (LCA) of two nodes p and q is:

```text
The lowest node in the tree that has
both p and q as descendants.
```

Example:

```text
          3
         / \
        5   1
       / \ / \
      6  2 0  8
        / \
       7   4
```

Suppose:

```text
p = 5
q = 1
```

Answer:

```text
3
```

---

# Solution 1: Path Storage (Brute Force)

## Idea

1. Find path from Root → p.
2. Find path from Root → q.
3. Store both paths in ArrayLists.
4. Compare both paths.
5. Last common node is the LCA.

---

## Example

Tree:

```text
          3
         / \
        5   1
       / \ / \
      6  2 0  8
        / \
       7   4
```

Suppose:

```text
p = 7
q = 4
```

Path to p:

```text
3 → 5 → 2 → 7
```

Store:

```java
[3, 5, 2, 7]
```

Path to q:

```text
3 → 5 → 2 → 4
```

Store:

```java
[3, 5, 2, 4]
```

Compare:

```text
3 == 3
5 == 5
2 == 2
7 != 4
```

Last common node:

```text
2
```

Therefore:

```text
LCA = 2
```

---

## Code

```java
class Solution {

    public TreeNode lowestCommonAncestor(TreeNode root,
                                         TreeNode p,
                                         TreeNode q) {

        List<TreeNode> pathP = new ArrayList<>();
        List<TreeNode> pathQ = new ArrayList<>();

        findPath(root, p, pathP);
        findPath(root, q, pathQ);

        TreeNode lca = null;

        int i = 0;

        while(i < pathP.size()
                && i < pathQ.size()) {

            if(pathP.get(i) != pathQ.get(i))
                break;

            lca = pathP.get(i);
            i++;
        }

        return lca;
    }

    private boolean findPath(TreeNode root,
                             TreeNode target,
                             List<TreeNode> path){

        if(root == null)
            return false;

        path.add(root);

        if(root == target)
            return true;

        if(findPath(root.left,target,path) ||
           findPath(root.right,target,path))
            return true;

        path.remove(path.size()-1);

        return false;
    }
}
```

---

## Time Complexity

Finding path to p:

```text
O(N)
```

Finding path to q:

```text
O(N)
```

Comparing paths:

```text
O(H)
```

Total:

```text
O(N)
```

---

## Space Complexity

Two paths:

```text
O(H)
```

Recursion stack:

```text
O(H)
```

Total:

```text
O(H)
```

---

## Interview Flag 🚩

### Why Is This Not Preferred?

Need extra storage:

```text
Root → p path
Root → q path
```

Need extra comparison step.

Correct solution, but not the most elegant.

# Solution 2: DFS + Recursion (Interview Expected)

## Idea

For every node:

1. Search left subtree.
2. Search right subtree.
3. If both sides return non-null:
   Current node is LCA.
4. Otherwise return whichever side found p or q.

---

## Code

```java
class Solution {

    public TreeNode lowestCommonAncestor(TreeNode root,
                                         TreeNode p,
                                         TreeNode q) {

        if(root == null)
            return null;

        if(root == p || root == q)
            return root;

        TreeNode left =
                lowestCommonAncestor(root.left, p, q);

        TreeNode right =
                lowestCommonAncestor(root.right, p, q);

        if(left != null && right != null)
            return root;

        if(left != null)
            return left;

        return right;
    }
}
```

---

## Why It Works

### Base Case

```java
if(root == null)
    return null;
```

Meaning:

```text
Did not find p or q.
```

---

### Found One Node

```java
if(root == p || root == q)
    return root;
```

Meaning:

```text
Found p
or
Found q
```

Return it upward.

---

## Three Possible Cases

### Case 1

```text
left != null
right != null
```

Example:

```text
      3
     / \
    5   1
```

Suppose:

```text
p = 5
q = 1
```

Then:

```text
left = 5
right = 1
```

Both found.

Therefore:

```java
return root;
```

Current node becomes LCA.

---

### Case 2

```text
left != null
right == null
```

Both nodes are somewhere in left subtree.

Return:

```java
return left;
```

---

### Case 3

```text
left == null
right != null
```

Both nodes are somewhere in right subtree.

Return:

```java
return right;
```

---

## Dry Run

Tree:

```text
          3
         / \
        5   1
```

Suppose:

```text
p = 5
q = 1
```

Execution:

```text
At Node 5:
returns 5

At Node 1:
returns 1

At Node 3:
left = 5
right = 1

Both non-null
```

Therefore:

```text
return 3
```

Answer:

```text
3
```

Each node is visited at most once.

```text
Time = O(N)
```

where:

```text
N = Number of Nodes
```

---

## Space Complexity

Recursion stack:

```text
Space = O(H)
```

where:

```text
H = Height of Tree
```

Balanced Tree:

```text
O(log N)
```

Worst Case (Skewed Tree):

```text
O(N)
```

## Why Is This Better Than Path Storage?

Path Storage:

```text
Need two ArrayLists
Need path comparison
Extra bookkeeping
```

DFS Solution:

```text
No path storage
No path comparison
Return information upward naturally
```

Cleaner and preferred in interviews.
